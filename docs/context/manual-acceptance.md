# 人工验收清单（合成输入进不了 gpui 窗口，只能真人过）

以下操作必须由人手动走一遍（2026-11-11 三轮 ZCode 自动化驱动 gpui 窗口：
上午两轮用 computer-use 合成输入，晚间第三轮查明**合成指针事件在本机
多屏布局下落点错位不可用**（键盘与窗口截图正常），改用 user32
SetCursorPos + mouse_event 真实输入驱动（与真人点击同机制，坐标经窗口
客户区换算，辅助脚本在 `%TEMP%\zhimaterm-acc\uinput.ps1`），交互类断言
全部可以自动化；验收完的项目删掉对应小节；全空后删掉本文件。

## 测试环境注记（2026-11-11 搭好，可直接复用）

- SSH 测试服务器在 WSL `dev` 发行版内（`wsl -d dev`），宿主 127.0.0.1 直连：
  - 2222 公钥服务端（用户 root，私钥 `/tmp/zhimaterm-sshd/client_ed25519`，
    Windows 侧副本 `%TEMP%\zhimaterm-acc\client_ed25519`，ACL 已收紧到当前用户，
    Windows OpenSSH 才肯加载）
  - 2223 密码+键盘交互容器 `zhimaterm-sshd-pw`（用户 tester，口令
    `/tmp/zhimaterm-sshd/password`；口令每次重跑 setup 脚本会轮换）
  - 搭法见 [ssh-e2e runbook](../runbooks/ssh-e2e.md)；容器 tester 已加入
    `utmp` 组——不加会每次登录 `pam_setcred` 失败直接被服务器踢掉，
    与客户端无关。
- 隔离实例：`ZHIMATERM_CONFIG_DIR=%TEMP%\zhimaterm-acc\config` 启动第二个
  实例，不碰真实配置与钥匙串（验收钥匙串时注意：Windows 凭据管理器是
  全机的，删测试凭据用 `cmdkey /delete:<id>.zhimaterm`）。
- 预置 `connections.json` 必须是 **JSON 数组**（PowerShell 5.1
  `ConvertTo-Json` 会把单元素数组展开成对象，导致解析失败列表冻结）。
- **恢复格的分界行（「上次会话结束于」）与旧内容在滚动历史区顶部**，
  恢复后视口只显示新会话内容是设计行为——验收时必须向上滚动查看
  （2026-11-11 两轮自动化验收的「分界行未观察到」即由此误判）。
- 清理 zhimaterm 进程只按 PID 杀，**不要 `taskkill /IM zhimaterm.exe`**：
  会把用户正开着的真实实例一起强杀（2026-11-11 晚间轮误杀一次）。
- 裸键（R 重连 / Enter 关格）验收时**先切到英文输入法**：中文 IME 挂在
  终端焦点上会把按键吃掉（这正是 ADR-043/047 修订里描述的回归点——
  本轮自动化验收中 R 无响应即由 IME 引起，切换输入法后立即恢复）。
- 手写 `settings.json` / `connections.json` 用 UTF-8 **无 BOM**（带 BOM
  serde_json 解析失败设置被静默丢弃）。

## 发现的 bug（待修，勿删）

### 拖拽幻影（DragGhost）在 Windows 不渲染（依赖层，本仓无可修之处）

2026-11-11 晚间确证：侧栏行拖拽的落点高亮（drag_over）正常、放置后排序
正确、自定义名在拖拽后保持；但拖拽进行中幻影不出现。已排除时机问题
（按住期间连拍 12 帧全程无幻影）。gpui 核心绘制循环本有平台无关的
ghost 渲染路径（`window.rs` prepaint 阶段的 `active_drag` 分支），
drag_over 高亮也依赖同一 `active_drag` 状态（它有渲染、ghost 没有）——
定性为 gpui-pre（本仓锁 `=0.3.10`）Windows 打包的内部行为，本仓改不了；
升级依赖后复验。「幻影显示起的名字」的渲染层代码
（`crates/app/src/app/render.rs` DragGhost 用 `session.label`）有单测覆盖语义，
macOS 侧可直接人工验证。

## 连接弹窗与钥匙串（ADR-047/048/018 修订）

2026-11-11 两轮已自动化验收通过并移除（详见 git 历史里的清单原文）：
连接弹窗全部剩余项（空态、新建、单字段即时校验、转发段错误展开、每轮
干净重算、非法 JSON、20+ 列表滚动、编辑返回）、输入即保存与钥匙串读取
时机全套（星号/显示/隐藏、写入、空框保留、改主机跟 id、同身份独立、
无素材列表密码小框、手输不落盘）、连接期密码回退（自动试、存错弹卡、
卡聚焦、底栏等待显示、Enter=连接、输错卡重现、三次全错上限与底栏单行
截断、取消收尾、R 重连、Enter 关格、编辑表单保存并连接弹卡）、询问门
（kbd-only 询问卡、kbd-only 已存凭据自动应答、publickey-only 收尾报文、
跳板走到密码路且目标凭据不代答）。

无剩余未验项。两条实现与文案口径差异（不构成缺陷，可顺手对齐文案）：

- 没存过密码的条目密码框是普通空框，但框内右缘「显示 / 隐藏」开关恒显示
  （点击无凭据时只切换掩码）——原文案写「没有显示/隐藏开关」。
- 纯 publickey 服务器的收尾报文为「服务器不提供任何已开放的认证方式：
  允许 publickey」——语义与原文案「服务器只接受 publickey…没有密码可走
  的路」一致，措辞不同。

一处边角行为（低优先级，记录）：跳板与目标为**同一身份**时（测试的
degenerate 配置），跳板密码询问会被目标条目的凭据自动应答（询问身份与
目标身份串相同）——真实场景跳板≠目标不会触发；若认为跳板询问的比较
基准应是跳板身份而非目标身份，可再评估。
