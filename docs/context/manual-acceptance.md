# 人工验收清单（合成输入进不了 gpui 窗口，只能真人过）

合成输入无法驱动真实的 gpui 窗口，以下操作必须由人手动走一遍。验收完的项目删掉
对应小节；全空后删掉本文件。相关 ADR 在「单测」或「验收」段落里指向本文件。

## 恢复格切 tab 的样式契约（2026-10-30，ADR-049）

- 双 tab 工作区（至少一个本地格有旧输出）重启后**直接切第二个 tab**：
  提示符在空屏顶部、旧内容与分界行在上方历史；满宽背景行（如 AI CLI
  命令块）不被撕成条纹、不与文字交错。
- 重启后**关闭一个从未切过去过的 tab**（等 >3 秒再关）：其回滚文件不被
  覆盖（重启同一工作区仍能恢复出旧输出）。
- 切到恢复格后手动拖窗口变高/变矮：标准终端行为（内容随行数增减在视口
  与历史间移动），无重复内容、无整备动作。
- zsh 与 bash 各一：切 tab 后提示符可见（SIGWINCH 重绘落在清屏后的空屏）。

## Windows cwd 恢复与新开格语义（2026-10-22）

- PowerShell 格：重启后恢复到**上次会话的启动目录**（PEB 采集）。注意边界：
  PowerShell 的 `cd` 不落进程 cwd，cd 后退出应用的目录无法恢复（ADR-039
  修订段）；设置里配置默认工作目录仍是 PowerShell 用户锚定目录的手段。
- cmd / 自定义 bash 类 shell 格：`cd` 到某目录 → 退出应用 → 重启，新 shell
  落在同一目录（这些 shell 的 cd 落进程 cwd，完整恢复）。
- 用户主动新开/重开的格：全新会话，**不出现**「上次会话结束于」分界行、
  不恢复任何旧输出（2026-10-22 拍板，孤儿接管已撤销）；分界行只出现在
  工作区恢复的格上。
- 探针面板（Windows）：进程行显示完整命令行，跑 `pi` 这类脚本的 node
  进程显示脚本名；详情弹层「可执行路径」「启动命令」有值（不再是一排 —）。

## 探针结束进程（2026-10-28，ADR-028 修订；Linux/Windows 实机 unverified）

macOS 已实机验收通过（端口行点开详情、面板内二次确认、kill 后采样闭环收尾）。
剩余两端各验一遍（无 macOS 之外的机器时可跳过，类型已交叉 check）：

- 进程详情 / 端口详情弹层有「结束进程」红按钮（根 shell 的详情没有）；
  点击弹**面板内**二次确认卡（叠在详情卡之上，不是窗口中央大卡片），
  「取消」/点遮罩回详情。
- 确认「结束」：详情卡出现「已发送结束信号…」，目标进程 ≤2 秒内从列表
  消失、弹层自动关闭（Windows 是 TerminateProcess 硬杀，应立即退）。
- 对已退出进程的陈旧弹窗点「结束」：不误杀复用该 PID 的新进程（exe 复核
  拒绝，弹层由采样关闭）。
- 端口占用进程是会话 shell 本身（如 ssh -L 经由会话进程监听）时：杀掉会
  断开转发/会话——这是允许的主动行为，只需确认弹层进程名可见、用户知情。

断线后底栏「N 秒后重连」应逐秒递减到 0 后发起重连（此前钉死在首次秒数，

## 侧栏会话行重命名（2026-10-27，ADR-047）

开两个本地标签 + 一个 SSH 标签，在第二个本地标签里跑 `vim` 让它有 OSC 标题：

- 右键任意会话行：菜单在指针处弹出，**活动标签不变**（终端区没有切换）。
- 菜单开着时：点终端区——只收菜单，终端**没有**收到点击（vim 里光标不动、
  无选区）；点另一行——只收菜单，不切标签、不起拖拽；按 Esc——只收菜单，
  vim **没有**收到 Esc（仍在插入模式则不退出）；敲普通字母照常进终端。
- 点「重命名」：弹输入框，光标已在框内可直接打字；占位显示当前自动标题
  （有 vim 时显示 vim 的标题，否则「会话 N」）。输入「生产库」Enter：该行
  第一行变「生产库」，窗口标题仍跟 vim；分屏后切焦点格名字不变。
- 再右键 → 重命名：框里预填「生产库」。清空后 Enter：回到自动标题。
  只输入空格 Enter：同样回到自动标题。Esc / 点遮罩：名字不变。
- 拖拽该行排序：拖拽幻影显示的是起的名字。
- 给本地标签起名后退出重启：名字保留（`workspace.json` 的 tab 带 `name`）；
  给 SSH 标签起名后重启：标签与名字一起不出现（既有口径）。
- 重命名对话框开着时按 ⌘W、⌘T：**什么都不发生**（标签不关、不新开、焦点仍
  在输入框、对话框不被顶掉）；Esc 关掉对话框后 ⌘W 立即恢复生效。连接表单、
  设置表单开着时同验（ADR-044 的 2026-10-27 修订）。⌘Q 在任何弹窗下仍可退出。

## 连接弹窗列表优先与连接名称（2026-10-27，ADR-048）

准备三条保存的连接：A（agent，起名「生产机」）、B（仅密码、未记住、不起名）、
C（agent，跳板只有密码素材）。

- 点侧栏「SSH」：弹窗直接是列表，没有表单；A 的标题是「生产机」、下行是
  `user@host:port · ssh-agent`，B 的标题是 `user@host:port`、下行 `密码 · 需输入`。
  每行右侧三个文字按钮：「连接」（强调色）、「编辑」、「删除」（灰字，悬停变红）。
  列表为空时显示空态文案与「新建连接」引导。Esc / 点遮罩 / 「关闭」都关弹窗。
- 点 A 行的标题/副行文字区域：**什么都不发生**（行本身不可点，也没有悬停高亮）。
- 点 A 行上的「连接」：弹窗关闭、新开 SSH 标签，侧栏该行标题是「生产机」；
  右键重命名仍可改。
- 点 B 行上的「连接」：叠出「输入密码」小框（输入框遮罩显示、光标已在框内、确认
  按钮「连接」），列表仍在底下。输密码 Enter：连上并关弹窗；Esc：回到列表，什么
  都不发生；留空 Enter：进入 B 的编辑视图，「密码」标签右边提示「这条连接需要密码」。
- 点 C 行上的「连接」：进入 C 的编辑视图，跳板段展开、「跳板密码」标签右边提示跳板
  只有密码素材；填跳板密码后「保存并连接」连上。
- 跳板端口往返（ADR-020 修订）：「新建连接」→ 开「经跳板机连接」，跳板主机填
  `bastion.example.com:2222`、跳板用户 `ops` → 「保存」。再点该行「编辑」：跳板主机框
  显示 `bastion.example.com:2222`；`connections.json` 里 jump 的 host 是
  `bastion.example.com`、port 是 2222（不是 host `bastion.example.com:2222`、port 22）。
  跳板主机填 `root@bastion:2222` → 「保存」：「跳板主机[:端口]」右边提示不要带用户名。
- 点 B 行上的「删除」：该行立即消失，条目数减一；弹窗不关、仍在列表视图。
- 点 A 行上的「编辑」：进入编辑视图（标题「连接设置」），名称框预填「生产机」，
  焦点在主机框；弹窗宽度与列表视图一致。改名为「预发」→「保存」：回到列表，
  A 的标题变「预发」，条目数不变。再「编辑」→ 把名称清空 → 「保存」：标题
  回到 `user@host:port`。
- 编辑视图里按 Esc / 「返回」：回到列表、改动丢弃、弹窗不关。回车 = 「保存」。
  Tab 沿「名称 → 主机 → 端口 → 用户 → …」走。
- 「新建连接」：空白表单、焦点在主机框；填完「保存」回列表多出一条；填完
  「保存并连接」直接连上关弹窗，标签初始名是填的名称（没填则「会话 N」）。
- 单字段校验错误贴在对应输入框的标签右侧（红字、与标签同字号），**随编辑即时消长**：
  空主机点「保存」→ 「主机」右边「请填写主机」；在主机框里敲入任意字符 → 提示
  **当场消失**（不用再点保存）；再清空主机 → 提示又出现。端口敲 `abc` → 不点保存，
  「端口」右边即出现「端口不是 1-65535 的数字：abc」，改回 `22` 即消。主机里粘
  `bob@a.example.com` 而「用户」已是 `deploy` → 失焦后「用户」右边出现「已经是
  deploy，主机里粘贴的是 bob：请二选一」。长文案在标签右侧换行，输入框宽度不变。
- 认证信息的组合结论进**底栏**，不贴任何输入框（2026-10-29 起保存不再拦
  「没有认证信息」——无素材也能存，结论由列表直连的素材判定产生）：关掉
  ssh-agent、不填私钥和密码 → 列表点「连接」→ 退到编辑视图、底栏「这条连接
  需要密码」。随后在密码框或私钥文件框敲任意字符、或拨 ssh-agent 开关 →
  底栏结论**当场撤掉**。
- 钥匙串失败贴**底栏**（2026-10-29 起，勾选行已不存在）：制造一次钥匙串写
  失败（如 macOS 锁定登录钥匙串后拒绝）→ 填密码 → 「保存」：底栏出现红字
  错误；修好后再「保存」：红字消失。
- 跳板/转发段里的错误把段展开：开「经跳板机连接」后收起跳板段、不填跳板主机 →
  「保存」：跳板段展开，「跳板主机[:端口]」右边「请填写主机」，填上即消。加一条
  空转发规则后收起转发段 → 「保存」：转发段展开，那条规则盒子里最后一行红字
  「本地端口不是 1-65535 的数字：」；填 `8080` 后红字变为缺目标的提示，补齐目标
  主机与端口后消失。刚添加、三个框都没填的规则不显示任何错误。
- 每次「保存」从干净状态重算：上一轮留在别处的错误全部清掉，只显示这一轮撞到的。
- 与字段无关的失败仍在底栏中间：把 `connections.json` 改成非法 JSON 后打开弹窗
  → 列表位置显示「保存的连接不可用」；此时「新建连接」填好点「保存」→ 底栏中间
  「保存的连接读不出来，先修好配置文件再保存」。
- 存 20+ 条连接：列表视图弹窗长到约八成窗高后内部滚动，不顶出窗口。

## 输入即保存与钥匙串读取时机（2026-10-29，ADR-018/048 修订）

准备一条存过密码的连接 R（密码 X），一条 agent 连接 A：

- 编辑表单里**没有「记住密码」勾选框**；密码框下方提示
  「输入并保存即写入系统钥匙串；留空沿用已存的」。
- 点 R 行上的「编辑」：密码框是**空的**（不回填），框内显示一串星号
  `********`（示意已存有密码）；「显示 / 隐藏」开关嵌在密码框**内**右缘。
  点「显示」：框里出现 X；再点换回掩码、内容还在。清空内容后星号示意
  重新出现。
- 没存过密码的条目（或新建连接）：密码框就是普通空框，没有星号、没有
  「显示 / 隐藏」开关。
- **输入新密码 → 保存**：钥匙串访问里该条目的凭据变成新值；重开编辑点
  「显示」取回的也是新值（2026-10-29 之前「没勾记住」导致不存的困惑消除）。
- R 空框直接「保存」：保存成功；点 R 行「连接」**能连上**（钥匙串里的 X
  没被空密码覆盖，也没有被删——删除凭据的唯一出口是忘掉连接）。
- 给 R 改主机名 → 「保存」：**钥匙串不动**（凭据按条目 id 挂，身份变了也
  是同一条）；列表里 R 原位更新为新主机名一行；点该行「连接」仍免输密码
  （ADR-018/048 修订：凭据跟条目 id 走，没有迁移这回事）。
- **新建保存同身份的第二条**（同 host/端口/用户再存一条）：列表**追加**成
  两行，互不影响；各自的密码各自独立（改其中一条的密码，另一条不受影响）。
- 新建连接**不填任何认证**（agent 关、无私钥、无密码）→「保存」：正常保存
  成一条；点行「连接」弹密码小框（连接期问密码的既有入口）。
- agent 条目 A 点「编辑」再「保存」：全程无钥匙串读取（macOS 不弹授权框）。
- **旧存档升级**（升级前存过密码的条目）：首次连接会要求重输一次密码
  （旧凭据按身份键存的，不再读取、当作没存过）；重输保存后恢复免输，
  钥匙串访问里新条目的账号是这条连接的随机 id。

## 连接期密码回退（2026-10-29，ADR-018/048 修订）

在 2223 密码服务器上准备一条 agent 条目，然后让本机 agent 不可用（退出
ssh-agent / 清空 SSH_AUTH_SOCK），验证认证失败后的现场询问：

- 点该行「连接」：**钥匙串里有这条的已存凭据时先自动试它**（不弹卡；此刻
  才读钥匙串）。存的密码正确 → 直接连上，全程无询问卡。
- 弹出「连接需要密码」卡时，**输入框自动聚焦**：光标已在框内、边框呈聚焦色，
  直接敲密码即可（无需先点框）；输入框是全 app 同一款 `TextInput` 组件。
  点框外卡片空白处不抢焦点、不触发终端选区/右键菜单（卡片按下不冒泡到
  终端容器）；点输入框本身可正常聚焦输入。
- 等待输入期间底栏显式 **「等待输入密码：user@host:port」**（秒表停走），
  不显示「正在连接…（Ns）」；输完提交后恢复连接状态显示。慢慢想密码不会
  导致超时——想多久都行（答复后连接预算重新起一段）。
- 卡上按 **Enter 即「连接」**（与列表密码小框同约定）；点「取消」或按钮
  也照常。
- 会话结束（三次全错、取消、断连、shell 退出）后：焦点自动从终端拿开
  （**点已结束的终端区也不会重新聚焦**），按 **R 重连有响应**（重新弹卡或
  连上）、Enter 关格生效——终端的输入焦点挂着 IME 处理器，焦点留在它上面
  时按键会被 IME 吃掉、写死会话报「无法再输入」（回归点）。
- 存的密码是错的（先改存错再试）：自动试失败后弹「连接需要密码」卡片，
  手输正确密码 →「连接」→ 连上；卡片手输的密码**不进钥匙串**（钥匙串访问
  确认无新条目）。
- 输错密码 →「连接」：认证失败后**卡片再次出现**可重输。
- 连续输错第三次仍错：不再询问，会话进结束态、底栏报「SSH 认证未通过」
  并列出各次尝试的原因（三次上限，防爆破）。原因串很长时底栏**保持单行**：
  文案右端截断出省略号，不换行、不把「R 重连 / 历史 / 记录」挤出版栏。
- 点「取消」：立即按无密码收尾，报「没有可用的认证信息…」。
- 无任何静态素材的保存条目点「连接」：先走列表上的密码小框（既有路径）；
  从编辑表单「保存并连接」（无素材）：弹窗关闭后终端区出现同一张询问卡。

## 询问门与身份随行（2026-10-29，ADR-018 修订补记）

前两节都在「服务端声明 password」的服务器上验收；本节覆盖门对齐与身份
隔离，其中键盘交互-only 形态可用测试容器临时改制（把
`/etc/ssh/sshd_config.d/00-zhimaterm-test.conf` 的 `PasswordAuthentication`
改为 `no` 后 `docker restart zhimaterm-sshd-pw`，验完改回），真机验收优先：

- **禁 password、只 keyboard-interactive 的服务器** + agent 条目（agent 里
  的钥匙不被服务器认）：连接后仍出现「连接需要密码」卡（修复前直接按
  「SSH 认证未通过」收尾）；手输正确密码 → 经键盘交互连上。
- 同形态下已有**已存凭据**：不弹卡，自动应答直接连上（凭据按条目 id 取，
  询问身份与目标比对一致才应答）。
- **纯 publickey 服务器**（连键盘交互也不开）：不弹卡，失败报文里带
  「服务器只接受 publickey…没有密码可走的路」。
- **跳板走到密码路**（跳板机 agent 失败、只有密码可走）：即使目标在钥匙串
  里有已存凭据，也**不会**拿它去自动应答跳板（跳板口令不落钥匙串），直接
  弹卡询问；输跳板密码 → 连通目标。
