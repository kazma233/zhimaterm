## Windows cwd 恢复与新开格语义（2026-10-22）

2026-11-11 已验收通过并移除：重启后恢复格落上次记录的工作目录
（workspace.json 每格 cwd）、cmd 的 `cd` 落进程 cwd → 退出 → 重启新 shell
落在同一目录（cmd 完整恢复）、当前设置的新默认 Shell（cmd）用于恢复与
新开的格、用户主动新开的格落在用户主目录全新会话且无分界行。

剩余未验：

- PowerShell 格的 PEB 边界：PowerShell 里 `cd` 不落进程 cwd，cd 后退出
  应用的目录无法恢复、重启仍落启动目录（ADR-039 修订段）——需要把默认
  Shell 换回 PowerShell 后重启观察一轮。
- 恢复格的**分界行**（「上次会话结束于」）：本轮自动化验收中恢复格只显示
  新会话内容，分界行与旧 scrollback 均未观察到——需真人确认分界行是否
  出现（若确实不出现则可能是 bug）。
- 探针面板（Windows）：进程行显示完整命令行，跑 `pi` 这类脚本的 node
  进程显示脚本名；详情弹层「可执行路径」「启动命令」有值（不再是一排 —）。
  ⚠️ 自动化验收中发现：cmd 格（用户指定 Shell）的格底栏没有渲染「进程」
  开关（`render_probe_bar` 应在 `probe_capable` 时恒渲染）——真人优先复核
  默认 Shell（PowerShell）格是否有开关；cmd 格没有则对照
  `probe_capable` 判定查是否 bug。

## 探针结束进程（2026-10-28，ADR-028 修订；Linux/Windows 实机 unverified）

macOS 已实机验收通过（端口行点开详情、面板内二次确认、kill 后采样闭环收尾）。
剩余两端各验一遍（无 macOS 之外的机器时可跳过，类型已交叉 check）：

- 进程详情 / 端口详情弹层有「结束进程」红按钮（根 shell 的详情没有）；
  点击弹**面板内**二次确认卡（叠在详情卡之上，不是窗口中央大卡片），
  「取消」/点遮罩回详情。
- 确认「结束」：详情卡出现「已发送结束信号…」，目标进程 ≤2 秒内从列表
  消失、弹层自动关闭（Windows 是 TerminateProcess 硬杀，应立即退）。
- 对已退出进程的陈旧弹窗点「结束」：不误杀复用该 PID 的新进程（exe 复核
  拒绝，弹层由采样关闭）。
- 端口占用进程是会话 shell 本身（如 ssh -L 经由会话进程监听）时：杀掉会
  断开转发/会话——这是允许的主动行为，只需确认弹层进程名可见、用户知情。

## 连接弹窗与钥匙串（ADR-047/048/018 修订）

2026-11-11 两轮已自动化验收通过并移除（详见 git 历史里的清单原文）：
连接弹窗全部剩余项（空态、新建、单字段即时校验、转发段错误展开、每轮
干净重算、非法 JSON、20+ 列表滚动、编辑返回）、输入即保存与钥匙串读取
时机全套（星号/显示/隐藏、写入、空框保留、改主机跟 id、同身份独立、
无素材列表密码小框、手输不落盘）、连接期密码回退（自动试、存错弹卡、
卡聚焦、底栏等待显示、Enter=连接、输错卡重现、三次全错上限与底栏单行
截断、取消收尾、R 重连、Enter 关格、编辑表单保存并连接弹卡）、询问门
（kbd-only 询问卡、kbd-only 已存凭据自动应答、publickey-only 收尾报文、
跳板走到密码路且目标凭据不代答）。

无剩余未验项。两条实现与文案口径差异（不构成缺陷，可顺手对齐文案）：

- 没存过密码的条目密码框是普通空框，但框内右缘「显示 / 隐藏」开关恒显示
  （点击无凭据时只切换掩码）——原文案写「没有显示/隐藏开关」。
- 纯 publickey 服务器的收尾报文为「服务器不提供任何已开放的认证方式：
  允许 publickey」——语义与原文案「服务器只接受 publickey…没有密码可走
  的路」一致，措辞不同。

一处边角行为（低优先级，记录）：跳板与目标为**同一身份**时（测试的
degenerate 配置），跳板密码询问会被目标条目的凭据自动应答（询问身份与
目标身份串相同）——真实场景跳板≠目标不会触发；若认为跳板询问的比较
基准应是跳板身份而非目标身份，可再评估。
