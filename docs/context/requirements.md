# ZhimaTerm 需求规格

状态：实现基线已确认并基本落地（P0/P1 见 gap 文档）。剩余待办唯一入口：
`docs/context/todo.md`（2026-10-21 建，聚合全部待办与明确不做项）。

## 1. 产品定义

ZhimaTerm 是面向开发者的独立桌面终端应用，不是可嵌入组件。应用提供本地 Shell、SSH 远程终端、多标签会话，以及与 SSH 连接关联的 SFTP 文件浏览和传输。

首批正式交付按阶段验收，不对外发布阉割原型。每个阶段均须达到可发布质量，后续阶段在已验收能力上扩展。

## 2. 技术基线

- 业务实现：Rust。
- 桌面 UI：`gpui-pre`。创建 `Cargo.toml` 时必须锁定实际采用版本及配套 platform crate。
- UI 侧异步设施：`smol 2`，用于 UI 事件回投与通道等待。
- VT 状态机：`alacritty_terminal`，仅负责文本终端状态与 ANSI/VT 序列解析。
- 本地 PTY：自研 `src/pty` 模块（ADR-025，移植自 portable-pty 0.9.0 语义）；首次跨平台构建时必须完成 macOS/Linux 专项验证。
- SSH/SFTP：Cargo crate `ssh2`（项目名 ssh2-rs），底层 `libssh2`。创建 `Cargo.toml` 时必须锁定 crate、TLS 后端和 vendored 构建 feature，并提交 `Cargo.lock`。可复现构建还依赖固定 Rust 工具链（`rust-toolchain.toml`，编译期下限见 `Cargo.toml` 的 `rust-version`）和 macOS/Linux 构建矩阵，不能仅以 vendored `libssh2` 作为保证。
- 序列化：`serde` 与 JSON。

Tokio 不作为应用统一运行时。若未来某个底层依赖明确要求 Tokio，只允许将其限制在该依赖的专属 worker 内，不能在 GPUI 主线程运行。

## 3. 支持范围

### 3.1 支持平台

- macOS。
- Linux。
- Windows（ConPTY）：与 macOS/Linux 同为一等支持，功能与验收标准一致。

### 3.2 会话类型

- 本地 PTY Shell：默认 Shell 与默认工作目录在设置中配置（Shell 从 `/etc/shells` 等系统
  注册表下拉选择，允许自定义路径；自定义路径必须是绝对路径，Windows 只接受 `.exe`/`.com`；
  工作目录必须是存在的目录，启动失败显式报错不静默回退），
  侧栏「本地」入口一键开新会话即用默认值；变更只影响新会话。终端尺寸随视图，
  不提供初始尺寸设置（2026-10-21 决策：分屏/标签模型下初始尺寸活不过首帧，属
  MobaXterm 独立窗口语义，见 ADR-036）。
- 本地 WSL Shell（仅 Windows，ADR-021）：经 ConPTY 启动 `%SystemRoot%\System32\wsl.exe -d <发行版> --cd ~`，完整套用本地格语义（无底栏、退出即收、无重连，ADR-016）；发行版从 Lxss 注册表现查枚举（含 `Modern` 项，过滤 docker-desktop/rancher-desktop 工具发行版），来源标签 `WSL · <发行版名>`。
- SSH Shell：认证素材叠加（agent、私钥文件、密码，见 §5 与 ADR-010），申请远端 PTY 并启动交互 Shell。
- SSH 连接关联的 SFTP：目录浏览、元信息读取、上传、下载、创建目录、删除、重命名和路径导航。
- SSH 端口转发（ADR-011）：本地转发、远程转发与动态 SOCKS 转发；规则随连接配置建立并持久化，运行中可在转发浮层增删规则并立即生效（2026-10-21 批次补齐 SOCKS 与动态增删）。单条规则失败不中止会话。
- SSH agent 转发（ADR-012）：会话级开关，默认关；把本地 agent 的签名能力延伸到远端，私钥不离开本机。
- SSH 连接保持（ADR-013）：keepalive 心跳（默认开，30s 间隔、3 个间隔无入向数据判死）；断线自动重连仅对认证成功过的会话生效，指数退避最多 5 次，可取消。
- 会话输出日志（ADR-017）：SSH 会话经底栏「记录」入口开关（只作用于本格本会话，不落设置），开启后输出以**终端渲染后的行文本**写入应用配置目录 `logs/` 下（折行接续、`\r` 重绘只记最终态、全屏程序的备用屏界面不记录）；只记输出不记输入，无回显的口令不落盘；每次会话尝试（连接、重连）各写一对首尾时间戳标记；本地会话不提供开关。

### 3.3 首版文本终端基线

- UTF-8、Unicode、组合字符、CJK 宽字符和 Emoji。
- ANSI SGR、256 色与 TrueColor。
- 光标、清屏、滚动区域、滚动历史和 alternate screen。
- 常用鼠标协议、bracketed paste、终端标题 OSC。
- 多标签会话及状态隔离。
- 关闭确认：用户显式关闭标签或分屏格（侧栏 ✕、⌘W、格内 ✕）前，若目标含未结束的 SSH 会话（连接与远端程序将被断开）或备用屏上有全屏程序在运行，先弹确认浮层；已结束的会话与空闲本地会话直接关闭，会话正常结束的自动回收不经确认。
- 终端分屏（ADR-014）：标签内二分嵌套，每格独立会话与状态底栏，比例拖拽。布局与窗口状态持久化见 §7（2026-10-21 前不持久化，本批次起实现，覆盖 ADR-014 初版取舍）。
- 界面骨架：终端区域直接顶到窗口上缘（无常驻顶栏）；会话身份（标题与来源 `LOCAL`/`WSL · <发行版>`/`user@host:port`）与响铃通知在侧栏会话行。会话行可右键「重命名」：用户起的名字盖过 OSC 标题与显示编号、只影响侧栏这一行、留空恢复自动标题、随工作区落盘（ADR-047）。侧栏底部固定一行会话入口「本地 │ WSL │ SSH」（WSL 仅 Windows，零发行版时隐藏），行尾是只显示三点色板的主题入口；顶栏右侧是 ⚙ 设置与 `?` 快捷键入口（ADR-041）。点击 WSL 入口弹出模态浮层选择发行版（默认发行版置顶带「默认」标记，其余按名排序，单个发行版也经选择确认），选定后开会话（ADR-021）。远端会话每格底栏承载功能入口（SFTP、转发）与常驻信息（监控、连接过程、结束原因与自动重连倒计时），运行中不占文案。本地会话（含 WSL）不设底栏，终端区域直接顶到窗口下缘；启动中、启动失败与终端不可写入在终端区域中央显示，启动失败同时给出关闭键位，本地会话不产生操作回执（ADR-016）。回看历史时，滚动起始的那一行内容左缘显示标记，随文字滚动。
- 终端内搜索（ADR-015）：搜索滚动历史与视口，增量搜索、大小写智能、正则开关默认关，命中高亮并滚动跟随。

首版不包含 Kitty 图像协议。该协议需要独立图像对象、纹理、滚动语义及资源上限设计，未来作为独立模块评估。

## 4. 运行时与会话模型

- GPUI 主线程只执行渲染、输入分发、状态更新和轻量事件合并；禁止同步 PTY、SSH、SFTP 或文件 IO。
- 每个本地 PTY 会话由专属 worker 持有 PTY 与子进程资源。
- 每个 SSH 会话由专属 worker 独占一个非阻塞 `ssh2::Session`；终端 channel 与 SFTP subsystem 只能经该 worker 串行调度。
- 远端 shell 退出不结束 SSH 会话：SFTP 句柄保持可用，会话由用户显式关闭（本地会话 shell 退出即结束）。会话关闭后 SFTP 句柄立即失效。
- SSH worker 以 socket 就绪事件驱动，在每轮循环中交替处理终端读写、SFTP 有界分块、命令和取消请求；不得以一次阻塞传输独占 worker。
- UI 仅持有可克隆的会话命令句柄、订阅状态和只读屏幕快照，不持有底层 PTY、SSH 或 SFTP 的 Rust 借用。
- worker 向 UI 发送有界事件；屏幕损伤更新可被新快照替换。关闭、认证、错误和传输终态属于控制事件，必须经不可合并的可靠路径传递；UI 订阅关闭时 worker 必须结束会话而不是无限等待发送。

## 5. SSH 信任与凭据

- 认证素材叠加（ADR-010）：本地 ssh-agent（开关默认开）、私钥文件路径（可选）、密码（可选）三者不互斥；按 agent → 指定私钥 → 密码（keyboard-interactive 先、password 后）的公开顺序尝试，全部失败时逐项报告原因，不做静默降级。agent 连接路径不提供配置，靠系统约定自动发现；找不到 agent 时在失败信息中说明。
- 必须校验应用受管理的 `known_hosts`；首版不修改用户的 `~/.ssh/known_hosts`。
- 主机身份由用户输入的目标主机名与端口组成；记录同时保存 host key 算法、原始公钥和 SHA-256 指纹。
- 首次遇到未知主机密钥时，由用户明确确认并显示算法和 SHA-256 指纹后才可写入记录。
- 已记录主机的密钥指纹变化必须拒绝直连并弹确认：用户核验新指纹并显式选择「信任新密钥」后才替换记录并继续连接，取消则中止；不能静默替换。
- 密码在表单里输入并保存时即写入操作系统安全凭据存储（ADR-018 修订：输入即保存，无「记住密码」勾选框；凭据按条目的随机 id 挂钥匙串，同身份的重复条目各有各的凭据；空框保存沿用已存的不覆盖）；删除凭据的唯一出口是忘掉连接，读不到凭据时回退为手输或连接期询问（临时密码不落盘）。
- 私钥由用户选择文件路径；应用不读取后持久化私钥内容，也不保存私钥口令。
- 连接配置中仅保存密码凭据引用，不保存密码明文。

## 6. SFTP 规则

- 上传和下载采用最大 1 MiB 的分块执行，并支持用户取消。
- 覆盖本地或远端同名目标前必须获得用户确认。
- 重命名不得静默覆盖。
- 上传先写入远端目标所在目录的临时文件，完成后优先尝试带 OVERWRITE|NATIVE 标志的 rename 提交。已知限制（2026-10-21 确认为做不了、后置，见 todo.md）：vendored libssh2 1.11 不分发 posix-rename@openssh.com 扩展，该标志仅在 SFTP v5+ 服务端生效；OpenSSH 等主流 v3 服务端上目标存在即失败，经用户确认的覆盖上传实际总是回退为直接写入目标（非原子，中断可能留下部分覆盖的目标，由临时文件路径之外的直写路径承担）。先删除旧目标再重命名始终禁止。
- 下载先写入本地目标所在目录的临时文件，再使用平台原子替换能力提交；不能原子替换时必须报告明确错误。
- 传输失败或取消后，worker 尝试清理自己创建的临时文件；清理失败须在任务终态中说明临时路径。
- 网络中断、认证失败、空间不足或权限不足时，当前任务失败并保留可读错误；首版不承诺自动重试或断点续传。
- SSH 会话关闭后，其 SFTP 句柄立即失效；进行中的传输应进入失败或已取消终态。
- 支持删除非空目录：客户端逐层遍历删除（不跟随符号链接），作为可取消的任务执行；非空目录删除前必须经用户确认。

## 7. 持久化与恢复

应用可以持久化会话配置、Shell 选择和工作目录（设置项，ADR-036）；窗口几何与标签/分屏布局
持久化在独立的 `workspace.json`（ADR-037，2026-10-21 批次实现）：只记本地格（含 WSL），
SSH 标签与格不持久化；混合标签在持久化时格级剔除 SSH 格、保留本地格的相对布局；重启后
窗口按保存几何恢复（与任何显示器不相交时回退默认居中），本地格自动启动**新** shell
（全新会话，不是恢复旧进程），全 SSH 标签不出现。标签在侧栏起的名字随布局一起落盘与恢复
（ADR-047；SSH 标签的名字随标签一起不持久化）。本地格额外恢复上次的工作目录与
最近一段带颜色与样式的回滚（每格 1,000 行 / 1 MB，新旧内容之间插分界行；
索引色随当前主题解析，真彩色保持原样；备用屏内容不保留，ADR-039/040）。SSH 连接保存认证素材的
引用（agent 开关、私钥文件路径）与转发规则（ADR-010/011）；口令与私钥口令不落盘，密码仅
以安全凭据存储引用持久化（ADR-018 修订：输入即保存，凭据按条目 id 挂钥匙串）。应用受管理的 `known_hosts` 存于应用配置目录。外观设置持久化在应用配置目录：终端字体只能从已安装等宽字体中下拉选择；界面字体从全部系统字体中下拉选择（含系统默认项），应用于全部界面文字但不影响终端网格；界面字号作为全局缩放根（rem）按比例缩放界面文字。保存失败不回滚当次已生效的界面，但必须明确报错。

应用重启后不自动恢复 SSH 连接、不自动执行 Shell 命令，也不自动重启未完成传输；SSH 必须
由用户显式重新连接。本地格是唯一例外：恢复布局时自动启动全新 shell（新建会话语义，
ADR-037），「必须显式新建」对本地格由布局恢复动作本身承担。

## 8. 初始性能验收提案

下列指标待目标硬件确认后生效：

- 同时运行 8 个本地或 SSH 会话。
- 活动终端支持 200 x 80 单元格，默认保留 10,000 行历史记录，并允许设置上限（2026-10-21 批次实现；此前固定 10k）。
- 单会话持续输出 10 MiB/s 文本时，输入进入核心命令队列的 P95 延迟不超过 50 ms，且 UI 事件队列不无界增长。
- 1 GiB SFTP 上传或下载期间，其他会话仍可交互；在连接可读写时，取消请求在 2 秒内到达已取消或失败终态。连接无响应时，2 秒后关闭该 SSH 会话并使其全部 channel 进入失败终态。
- 连续创建和销毁 100 个本地及 SSH 会话后，不遗留子进程、连接或平台句柄。

## 9. 分阶段交付

1. 本地终端核心：本地 PTY、VT 适配、屏幕损伤模型、GPUI 终端视图与 macOS/Linux 测试。
2. SSH/SFTP：严格主机密钥校验、认证、远端 Shell、非阻塞 SSH worker、SFTP 任务调度、传输与错误处理。
3. 工作区能力：多标签、SFTP 文件树、传输任务、配置持久化和安全凭据集成。
4. 兼容性与性能：性能基准、资源泄漏测试、协议扩展与 Windows ConPTY（已落地为一等支持，原「评估」措辞失效）。

## 10. 验收证据

- 单元测试：VT 适配、输入编码、命令/事件调度、传输状态机、覆盖确认与路径规则。
- 集成测试：本地 Shell、SSH 密码/私钥认证、known_hosts 未知与指纹变化、SFTP 成功/取消/权限失败/断线。
- SFTP 兼容性测试：支持与不支持原子覆盖 rename 扩展的服务端；不支持时必须证明既有远端目标未被删除或部分覆盖。
- 平台测试：macOS、Windows 与 Linux 的 resize、Shell 退出、会话关闭和子进程回收。
- 性能测试：按第 8 节固定输入数据和目标环境执行，并记录结果。
- 人工交互验收：宽字符、输入法、鼠标协议、复制粘贴、多标签和文件操作确认弹窗。
