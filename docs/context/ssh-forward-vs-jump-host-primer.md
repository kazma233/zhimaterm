# 端口转发 vs 跳板机：大白话版

写给没用过（或每次都要现查）这两个功能的同学。不说术语，先说人话，再看图。

## 一句话说清

- **端口转发**：把「服务器背后摸不着的服务」**搬到你面前**用。
- **跳板机**：给你「登录进内网机器」**铺一条路**。

一个是搬**服务**，一个是铺**路**。下面逐个看。

---

## 一、端口转发：把服务搬到你面前

### 场景

你笔记本在家，公司数据库 `10.0.0.2:3306` 只有一台服务器 `server` 能访问。
你俩之间唯一能通的，是你到 `server` 的 SSH 登录。

### 它干了什么

在 SSH 连接里**再塞一条加密隧道**，两端各开个小口：

```
              SSH 加密隧道（就是你已经登上去的那条连接）
 ┌──────────┐ ══════════════════════════════════ ┌──────────┐
 │ 你的电脑  │                                   │  server  │
 │          │                                   │          │
 │ :3306 ◀──┼── 小口A ──────────── 小口B ──────▶ ├──▶ 10.0.0.2:3306
 └──────────┘                                   └──────────┘
   Navicat 连                                        真正的数据库
   localhost:3306                                   （在服务器背后）
```

之后你用 Navicat 连 `localhost:3306`，数据其实全程走的是这条加密隧道，
在公网上裸奔的流量都被 SSH 包住了。

**关键点：你登录的还是 `server`，从头到尾没有「登录」过数据库那台机器。**
你只是借了 server 的手，把数据库的口子接到了自己桌上。

### 三个方向（记两个就够）

```
本地转发（最常用）          远程转发（偶尔用）
服务在远，搬到本地           服务在本地，给远端用
┌────┐    ─────▶    ┌────┐  ┌────┐    ◀─────    ┌────┐
│你   │   隧道       │服务器│  │你   │   隧道      │服务器│
└────┘              └────┘  └────┘              └────┘
连内网数据库、           调试用：让服务器访问
远端 Web 服务            你电脑上跑的接口
```

| 我想要… | 用哪个 | 例子 |
|---|---|---|
| 本地工具连内网数据库/Redis | 本地转发 | `localhost:3306` → 内网库 |
| 浏览器打开服务器背后的后台 | 本地转发 | `localhost:8080` → 内网管理页 |
| 让服务器回调我电脑上的接口 | 远程转发 | 微信/webhook 联调 |

## 二、跳板机：给登录铺路

### 场景

公司有台内网机器 `10.0.0.5`，你从外面**根本 ping 不上它**。
唯一的门是堡垒机 `jump`——你能连上它，它能连上 `10.0.0.5`。

### 土办法：手动登两次

```
第一步：ssh me@jump          （登上堡垒机）
第二步：ssh me@10.0.0.5      （在堡垒机里再登一次目标）
```

能用，但很难受：

- 复制粘贴文件（SFTP）、拖日志，都要在堡垒机上倒一手；
- 密码要在堡垒机的屏幕上再敲一遍；
- 断线了要从头再来一遍。

### 跳板机 / ProxyJump：一条命令直达

```
ssh -J me@jump me@10.0.0.5
        │
        └─ OpenSSH 自动帮你完成的动作：
```

```
 ┌────────┐  SSH连接①   ┌────────┐  SSH连接②(藏在①里面)
 │ 你的电脑 │ ═════════▶ │  jump  │ ════════════════════▶ ┌──────────┐
 └────────┘             └────────┘   走的是连接①的一条通道   │ 10.0.0.5 │
                                          ↑               │  内网目标  │
                                     外网只见①             └──────────┘
```

**关键点：你面对的始终是目标机。** 提示符、传文件、看日志，都像
`10.0.0.5` 直接连在你电脑上一样；堡垒机只是被借道，你在它上面什么
都不用敲。

### 代价：要过两道门禁

```
        ┌─ 门禁①：验你 ──────▶ 验堡垒机
 登录 ──┤
        └─ 门禁②：验你 ──────▶ 验目标机
                                （各自要密钥/密码，互不相通）
```

也就是说：堡垒机的钥匙和目标机的钥匙是**两套**，「记住密码」也要分别记。

---

## 三、它俩的关系（一句话）

跳板机的底层就是拿「端口转发」拼出来的：在堡垒机的连接里开一条隧道，
通到目标机的 22 端口（SSH 自己的端口），再让目标机的登录走这条隧道。
所以先有转发、后有跳板，是同一套积木搭出来的两种玩法。

## 四、怎么选：一张决策树

```
你的问题是哪种？
│
├─ 「我想【用】那台服务器背后的某个服务」
│   （连数据库、开后台页面、调接口）
│            │
│            ▼
│      ➜ 端口转发
│
└─ 「我想【登进】那台机器敲命令 / 传文件」
    （它在内网，只有堡垒机能碰到它）
              │
              ▼
        ➜ 跳板机
```

再给一张速查表：

| | 端口转发 | 跳板机 |
|---|---|---|
| 解决什么 | 用到摸不着的服务 | 登进连不上的机器 |
| 你登录谁 | 还是原来那台服务器 | 最终目标机（堡垒机只过路） |
| 认证几套 | 1 套 | 2 套（跳板 + 目标各一套） |
| 搬的是什么 | 某个端口的流量 | 你的整条登录连接 |
| 命令长相 | `ssh -L 3306:内网库:3306 server` | `ssh -J jump target` |

## 五、zhimaterm 里的现状

- **端口转发**：已支持（本地/远程，ADR-010/011）。开关在终端底栏右缘的
  「转发」按钮里，随连接生效。
- **跳板机**：已支持（单级，ADR-020）。连接表单勾「经跳板机连接」，填跳板的
  主机[:端口]/用户/认证素材即可；跳板与目标各过一次主机确认与认证，
  跳板密码只在内存里（不进钥匙串）。多级链式暂不支持。

> 一个容易混的近邻：`~/.ssh/config` 的 `Host` 别名只是「给连接起外号」，
> 不改变上面的任何路径——zhimaterm 有意不做这块（ADR-002 边界）。
