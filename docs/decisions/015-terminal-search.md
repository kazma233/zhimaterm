# ADR-015:终端内搜索（滚动历史）

状态:已接受(2026-10)

## 背景

MobaXterm 差距分析 P0 #5:翻滚动历史查日志是日常高频操作。早前拷问轮已定
共识:`⌘F` 底部搜索条、视口+全部滚动历史、增量搜索、大小写智能、正则开关
默认关、高亮当前匹配并滚动跟随。

## 决策

### 搜索在哪执行

- **worker 侧**,用 `alacritty_terminal` 自带的 `RegexSearch` +
  `Term::search_next`:滚动历史只在 worker 的 `TerminalModel` 里,画面快照
  不携带历史,UI 侧无从搜起。这也是 alacritty 自身的实现路径,语义(跨格
  匹配、宽字符、边界)与上游一致。
- 搜索状态归 worker:当前模式串与当前匹配。UI 只发命令、收结果。

### 匹配边界(上游语义,固化为取舍)

- **单次匹配不跨行**:上游 DFA 逐格喂字符,行边界按"输入结束"处理
  (`next_eoi_state`),因此 `needle\s+next` 这类跨行模式不会命中。搜索
  **范围**仍覆盖视口与全部滚动历史(逐行扫),只是单条匹配落在一行内。
- 高亮因此至多一段(行号 + 列区间);不需要多段高亮的表示。

### 命令与结果协议

- 新命令 `Search { pattern, direction, regex }`:UI 每次编辑(增量)发一次
  `Forward`,回车/⇧回车发 `Forward`/`Backward` 从当前匹配继续;关闭搜索条
  发 `ClearSearch`(清状态,高亮消失)。
- 模式串语义:**正则开关默认关**——关时模式串按字面匹配(转义全部正则
  元字符);开时交给 `RegexSearch` 原样编译,编译失败回报「正则无效」。
  **大小写智能**沿用 `RegexSearch` 内建行为:模式串全小写时不区分大小写,
  含大写则区分。
- 结果走两条既有路径:
  1. **匹配高亮进画面帧**:快照新增「当前匹配」字段(视口行号 + 列区间;
     单行内一段,见上节边界),由网格绘制层叠加高亮;不进控制事件(帧是
     可合并的瞬态展示数据,与转发状态同一归类)。
  2. **是否命中与位置走控制事件**:`SearchResult { matched, grid_line }`,
     供搜索条显示「已高亮 / 无匹配 / 正则无效」;`grid_line` 是匹配首行
     的绝对行号(回看第几行),供状态展示。

### 滚动跟随

- 命中即把匹配行滚进视口:匹配在历史深处时按「视口中部」对齐,在当前
  屏内则不动视口(避免每次按键都跳)。
- 搜索期间用户的滚轮操作不受限(还是自由的);下一次搜索命中重新对齐。

### UI(底部搜索条)

- `⌘F`(macOS)/ `ctrl-shift-f`(非 macOS,Windows Terminal 与 GNOME
  Terminal 同键位)打开,焦点进输入框;Esc 关闭并清除高亮。
- 条内:输入框 + 正则开关(默认关) + 匹配反馈 + ✕。输入即时增量搜索;
  回车下一个、⇧回车上一个。
- 搜索条是终端视图内部的覆盖层(absolute 贴底),不挤占网格——网格尺寸
  不因搜索开关变化,PTY 不被无谓 resize。

## 后果

- `TerminalModel` 新增搜索入口(执行搜索 + 视口对齐)与快照的匹配字段;
  `SessionCommand`/`ControlEvent` 各扩一项。
- 大小写智能与跨行匹配语义来自上游 `RegexSearch`,不自研匹配器;
  字面模式的转义只处理正则元字符集合。
- 门控 e2e 增加一条:本地会话灌入已知内容(含滚动历史)→ 搜索 → 帧里
  出现高亮且视口对齐;纯单测覆盖智能大小写/字面转义/正则开关/无匹配。
- 搜索不改变选区、复制与鼠标协议的任何语义;高亮只是绘制叠加。
