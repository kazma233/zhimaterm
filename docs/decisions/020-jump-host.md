# ADR-020:跳板机/ProxyJump(单级)

状态:已接受(2026-10)

## 背景

P1 #10(`../context/mobaxterm-gap-and-priorities.md`):目标机在内网、只能经堡垒机访问的
用户每次连接都需要,频率 100%。OpenSSH 的对应能力是 `-J`/`ProxyJump`,其
实现方式是经跳板开一条到 `目标:22` 的通道,目标会话的 SSH 字节流走这条通道。

zhimaterm 的会话层(pump、等待、信任、认证、SFTP、监控)全部围绕「一个
libssh2 会话绑一个 socket」构建;ssh2 crate 未暴露 libssh2 的自定义
IO 回调,无法把「目标会话的传输」直接挂到跳板会话的 channel 上。

## 决策

### 传输:回环桥,不改会话层

`ssh::open` 在目标带 `jump` 配置时,先完整建立到跳板的会话(握手 → 主机
信任 → 认证,全部复用既有函数),在其上开 `direct-tcpip` 通道指向
`目标:22`;同时在 `127.0.0.1:0` 建一对预连接的 TCP(监听方归桥接线程,
发起方交给后续流程当"目标的 socket")。专用桥接线程双向搬运:

```
目标 SSH 会话 ←→ 127.0.0.1 TCP 对 ←→ direct-tcpip 通道 ←→ 跳板会话 ←→ 跳板
```

这与 OpenSSH `-J` 的 ProxyCommand 管道桥接同构,目标会话的握手、信任、
认证、pty、shell、LANG、SFTP、监控全部零改动。桥接线程复用 poll/
唤醒原语与 keepalive 语义(30s 心跳、90s 静默判死,ADR-013 同款),
失败表现为本地端 EOF——目标会话按既有「连接断开」路径终态,自动重连
资格判断照常生效。

暴露面与既有本地转发(ADR-011)同级:listener 只绑 127.0.0.1,桥上
流量是目标 SSH 的密文;预连接在返回前完成,不留被抢连的窗口。

### 生命周期

桥接线程与跳板会话的句柄封装为 `JumpGuard`,挂在目标会话的
`SshControl` 里;关闭顺序:目标 pump 先停,再 Drop guard(唤醒并
join 桥接线程、关闭跳板会话)。重连从 `SshTarget` 副本重建整条链
(跳板也要重连、重新过信任与认证)。

### 配置:单级跳板,独立的一套目标描述

`SshTarget` 增加 `jump: Option<Box<SshJump>>`;`SshJump { host, port,
user, auth: SshAuth }`——跳板不需要 forwards/logging/agent 转发,那些
属于目标会话。v1 只支持单级(不链式);多级若有真实需求再扩展为链表,
不预做抽象。

### 信任与认证:两套各自独立

跳板先过一次主机密钥确认(`TrustRequest` 带跳板的主机与指纹),认证
素材独立(agent/私钥/密码,与目标无关);然后才是目标机的信任与认证。
保存的连接为跳板持久化 host/port/user/凭证引用(SavedCredentials 同构),
**跳板密码不写钥匙串**(ADR-018 的记住密码只覆盖目标;跳板密码只在
本次连接的内存里),这是 v1 的已知取舍。

## 后果

- 连接表单增加可选「经跳板机」区(开关 + 主机[:端口]/用户/认证素材)。
- 来源描述(`SshTarget::description`)带跳板路径,形如
  `目标user@host:port 经 跳板user@host:port`——侧栏来源标签、连接中文案
  与会话日志首标共用它,排障时一眼可辨(修订:最初写"侧栏仍是目标"与
  实现取舍不符,信息价值优先,落此口径)。
- 跳板路径多一个本地回环中转与一根桥接线程,SSH 密文吞吐无感知;
  每次连接对跳板是一整套握手+认证(与 OpenSSH 相同)。
- 目标断线重连会重新走跳板全流程;跳板断开同样表现为目标会话断开。
- 门控 e2e 用 2222(公钥)当跳板、2223(密码)当目标覆盖全链路。
- 多级跳板(`-J a,b,c`)、跳板密码进钥匙串:待真实需求再立项。

## 修订（2026-10-27）：「主机[:端口]」的拆分此前并未实现

表单的跳板目标框一直按「主机[:端口]」标注，载入已保存连接时也把非 22 端口拼成
`host:port` 回填；但保存与连接时整串被原样当成主机名、端口固定 22——填
`bastion:2222` 会存成主机 `bastion:2222`、端口 22，再载入回填的还是那一串，
往返看着一致、连出去却是错的。修正：`ConnectForm::parse_jump_target` 用主表单
同一套 `split_destination` 拆目标（端口缺省 22，IPv6 方括号写法同样覆盖），保存
与连接走同一份解析；`user@` 不静默并入「跳板用户」，报错指过去。单测
`jump_target_splits_host_and_port` 守住拆分、缺省、往返与两条报错。此前存坏的
条目下次保存会自动拆正（载入回填的 `bastion:2222` 现在被当作 host:port 解析）。
