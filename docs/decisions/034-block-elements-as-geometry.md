# ADR-034：块元素按格子几何绘制

状态：已接受（2026-10）；2026-10 修订：制表线按同一规则扩入几何表

## 背景

opencode、pi 这类 TUI 用块元素（U+2580–U+259F：█▀▄▌▐░▒▓ 与象限）拼 logo、
进度条与 sparkline。zhimaterm 里这些 logo 的行与行之间有横向白缝（用户标注
对照 kitty：同一段 art 在 kitty 里无缝）。

根因在绘制层：格高 = (ascent − descent) 向上取整（Menlo 13px：15.13 → 16），
而 `█` 走字体字形，只覆盖字体自己的行框（15.13px），gpui 又把行框在格内垂直
居中——每行上下各留约 0.4px，逐行叠加成肉眼可见的缝。这是字体字形与
「格子几何」两套度量的系统性偏差，不是某个字体或字号的偶然问题；kitty 的
做法是这类字符完全不用字体字形，按格子几何画。

同样的偏差在制表线上更刺眼：opencode 的消息框/输入框用 `│` 画左边框，
竖线每行断出 1px 缝，整条边框呈虚线（对照 ghostty：同一边框连续）。
当初 ADR 划定「制表线暂不入表，实际遇到再扩」，即为本次修订的依据。

## 决策

块元素（U+2580–U+259F，全部 32 个）与制表线（U+2500–U+2570、U+2574–U+257F，
共 125 个）在视图层按格子几何绘制，不走字形路径：

- **模型层**：`TerminalRun`/`RunStyle` 增加 `block` 标记（`is_block_element`）。
  这些字符不与普通文字合并成段（混段就无法整段跳过字形路径）；彼此之间照常
  合并（绘制按格逐簇取几何，一段混多种几何字符没有问题）。
- **几何表**：`block_geometry` 覆盖全部 157 个码点——上下块与整格按 1/8 分档，
  左右块与 ▔▕ 同理，象限组合是半格矩形表，░▒▓ 是整格灰度（alpha 1/4、1/2、
  3/4，kitty 画棋盘格，平均覆盖相同）。制表线规格：
  - 线宽：细线 = 竖线 1/8 格宽、横线 1/16 格高（默认字号下都 ≈1px，对齐
    Menlo 笔画）；粗线 = 2× 细线。线沿格子中线。
  - 双线 ═║ = 中线 ±1/8 处的两条细线；单双混合连接件按臂取各自的线型。
  - 圆角 ╭╮╰╯ 按直角画：quad 画不了弧，Alacritty/kitty 同约定。
  - 虚线 n 段等长，段长 = 间隔 = 1/(2n−1)，首尾贴边（╌ 2 段、┄┆ 3 段、
    ┈┊ 4 段），`dash_rects` 常量函数生成。
  - 连接件的臂矩形拆成常量表（VL/VH/HL/HH 各臂、双线半臂），每字符是
    1–4 个臂的组合，映射以 Unicode 官方名称为唯一事实源。
- **绘制**：`paint_block_run` 沿段逐簇取几何，连续同字符并成一块画（同色
  四边形相接不露缝；整宽单矩形跨段合并，横线受益）；其余逐格画——竖线
  矩形占满整格高，相邻行的四边形精确相接，不再有字形行框的缝。前景色走
  通用的反相口径——光标块、选区压在这些字符上时颜色自然正确。
- **边界**：带下划线/删除线的块元素仍走字形路径（装饰线随字形画）；对角线
  ╱╲╳（U+2571–U+2573）不标记、不入表——轴对齐矩形画不出斜线，且它们单格
  内不成缝，字形路径即可；盲文点阵（U+2800+）仍不在范围，遇到再按同一
  规则扩表。

## 后果

- 块状 art、进度条、sparkline、TUI 边框逐行/逐格无缝，且宽高精确对齐网格
  （字形反锯齿的半透明边缘消失，块边缘更锐）。
- 字形路径跳过 = 每帧少整形/少画这些字符，块 art 密集的画面更快；用户选
  了缺制表符字形的字体也不会再出现豆腐块。
- 灰度字符 ░▒▓ 的观感从「字体棋盘」变成「半透明覆盖」，与 kitty 的平均
  亮度一致，图案细节略有差异。
- 线宽是格子分数而非像素：换字号/换字体时笔画随格宽缩放（与字体行为
  一致），但极端宽高比的字体里横竖线粗细会略有差异。
- 几何表与 Unicode 定义一一对应，新增范围（盲文/legacy computing）只需扩
  `block_geometry` 一处；守卫测试强制「模型标记 ⊆ 几何表」。
