# ADR-055：文件路径点击与编辑器打开

状态：已接受（2026-11-11）。

## 背景

终端输出里最常见的「可操作文本」除了 URL 就是文件路径：编译器报错
（`src/main.rs:12:5`）、grep 结果、`ls` 输出。URL 识别（ADR-002 的 hints
补充决定）已把这些文本里的链接变成可点击，路径却不行——用户只能选中、
复制、切到编辑器、粘贴。

路径与 URL 的本质差异：URL 的打开目标是**网络**，路径的打开目标是**本机
文件系统**。ADR-002 拒绝识别 `file://` 的理由（「防止诱导打开本地目标」）
正面挡在这条路上：远端输出可以让屏幕出现任意路径文本，把它直接映射为
本地打开动作，等于把远端内容接到宿主的文件系统与编辑器上。

## 决策

### 1. 识别与 URL 分轨，动作语义进契约

快照 run 的链接字段从 `Option<Arc<str>>`（uri）改为枚举 `TerminalLink`：
`Url(Arc<str>)` 与 `FilePath { path, line, column }`。URL 走既有交互
（⌘/Ctrl+点击直接交给系统）；路径是另一类动作（本地编辑器打开），
打开分派、安全边界与行号定位都按变体走，视图不猜字符串形态。

识别规则（与 URL 同在快照构建时进行，按**软换行逻辑行**拼接识别、无持久
状态——2026-11-13 起与 URL 同步从单行识别改为跨软换行拼接，见 ADR-002
的修订段）：

- 形态：绝对 POSIX 路径 `/seg/…/seg`、家目录前缀 `~/…`、Windows 盘符
  `C:\…`/`C:/…`；段字符集含 unicode 字母（中文文件名），前缀边界检查只看
  ASCII（与 URL 的同类检查一致）。相对路径不识别——屏幕旧行对应的 cwd
  无法追溯，误报远多于收益。
- 可选尾部 `:行[:列]` 后缀捕获为定位信息（`path` 字段不含行号）；
  尾部句点/逗号/分号剥除。命中范围含定位后缀整条（点击行号也算点路径）。
- URL 识别占列优先：`https://…/x.rs` 的 path 段不产生二次路径链接。
- 文本白名单（后缀集合 + 知名无后缀文件名/dotfile 集合，大小写不敏感）
  在识别层拦下非文本目标——编辑器语义是打开文本，白名单把二进制与
  无意义匹配挡在悬停之前。清单是代码里的显式集合（`terminal` crate），
  按需增补。

### 2. 仅本地会话响应，存在性验证在视图层

- **SSH 会话不响应路径**（悬停不亮、点击无动作）：屏幕上的路径是远端
  路径，本地编辑器打不开；这延续 ADR-002 对 file:// 的拒绝——不把远端
  输出映射到本地打开动作。识别层不分会话类型（模型不知道会话来源），
  视图按 `local` 标志裁决。
- 本地会话（含 WSL 格，ADR-021 语义）在**悬停与点击时**做 `~` 展开后的
  存在性检查（`exists()`），不通过不亮也不弹。验证不进快照热路径——
  快照是每帧操作，查盘只发生在指针交互时（格粒度，一次 stat）。
  WSL 格当前命中的是**宿主路径**；子系统内路径（`/home/...`）的
  `\\wsl.localhost` 转换是后置项（见「不做与后置」）。

### 3. 打开必须经二次确认

⌘/Ctrl+点击路径不直接打开，先在点击位置弹确认浮层（与右键菜单同一
挂载与定位机制的指针锚定小卡片，ADR-023/027 同款：视图持锚点、遮罩只盖
本格区域、不入 ADR-044 浮层栈、不接焦点）：显示「在 {编辑器} 中打开
{路径}」+ 打开/取消；Esc 收起。这一下仍然是显式用户动作（修饰键点击），
确认卡挡住「输出诱导的意外打开」，也挡住误点。

打开失败（档位编辑器被卸载、spawn 失败）静默：本地格没有底栏与回执
通道（ADR-016），设置保存时的路径校验已挡住绝大多数坏值；为这一个场景
铺 toast/通知通道不值。URL 打开维持现状（直开、无确认）。

### 4. 编辑器档位与发现链

设置新增 `text_editor`：`None`=系统默认文本编辑器（macOS `open -t`、
Windows `notepad`、Linux `xdg-open`）；`vscode`/`zed`=档位 id；其余值=
自定义可执行文件绝对路径（校验规则与 `local_shell` 同源：绝对路径、
存在、可执行，Windows 只收 .exe/.com）。设置存**档位 id 而非解析结果**，
打开时走发现链重解析——编辑器升级/移动不需要迁移设置：

- 静态已知安装位置（macOS `.app` 包内 CLI、Windows `%LOCALAPPDATA%\Programs`、
  Linux `/usr/bin` 等）→ PATH 兜底。探测在 `local::editors`（与 `shells`
  同纪律：只列候选不决定），设置下拉与打开动作共用。
- Windows 的 VS Code 直接 spawn `Code.exe --goto`，不走 `code.cmd`
  （脚本 CLI 需经 cmd、闪 console，还违反 .exe/.com 规则）。
- 行号传参按编辑器能力：VS Code `--goto path:line:col`、Zed 原生
  `path:line:col`；系统默认与自定义忽略定位只开文件。
- 档位编辑器探测不到（卸载）不静默降级系统默认——打开失败返回，
  用户回设置页能看到档位已不在候选里。设置应用时档位即推给全部
  已开会话（与字体同一时机），新会话建立时带上。

## 不做与后置

- **不支持 `$EDITOR`**（Warp 支持）：GUI 进程 spawn TUI 编辑器（vim/nano）
  没有 tty 会挂死；要支持得把路径开进终端新标签，是另一个功能维度。
- **不查 Windows App Paths 注册表、不解析 Linux .desktop 数据库**：分别是
  两平台的「应用注册」正统机制，但要引 `winreg` 依赖/处理 flatpak 的
  Exec 包装；静态表已覆盖官方默认安装位置，非默认安装有自定义兜底。
- **WSL 子系统路径转换**（`/home/...` → `\\wsl.localhost\...`）、
  **相对路径 + 按行 cwd 历史**、**SFTP 拉取远端文件副本后打开**：
  各自是独立的功能量级，本 ADR 不承诺。
- **自定义命令模板**（`{file}`/`{line}` 占位符，Warp 式）：无真实需求前
  不加；自定义路径按裸开文件处理。

## 实现落点

- `terminal`：`TerminalLink` 枚举、`plain_path_links`（与 `plain_url_links`
  并列，复用同一行文本/格偏移 scratch）、文本白名单集合、契约测试
  `plain_text_paths_reach_the_snapshot`。
- `local`：`editors` 模块（`EditorKind`、`candidates()` 发现链）。
- 根包：`editor.rs`（档位解释 `EditorChoice::from_setting`、`~` 展开、
  参数构造、spawn）；`terminal_view` 的悬停/点击分派与确认浮层；
  `terminal_keys` 的 Esc 守卫链（确认浮层最前）；设置表单的编辑器下拉
  （与 Shell 下拉共用的三态模式）；app 持有档位并在设置应用/新会话时推送。

## 验证

- 路径识别单元测试：绝对路径/`~`/盘符/行号捕获/URL 内不重复识别/
  白名单外不识别/无后缀文件名/宽字符列对齐/词中片段不识别。
- 三后端契约测试守住路径识别的后端一致性。
- 档位解析与参数构造（`--goto`、Zed 原生、忽略行号）的纯函数测试。
- 设置往返测试覆盖档位下标解析；校验测试覆盖自定义路径规则。
- 手工 e2e：本地会话输出路径 → 悬停亮 → ⌘点击弹确认 → 打开并定位；
  SSH 会话同样输出不响应；自定义路径校验拦截坏值。
