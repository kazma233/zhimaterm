# ADR-048：连接弹窗列表优先、编辑与连接分离、连接名称

状态：已接受（2026-10-27）。

## 背景

SSH 弹窗此前是左右两栏：左栏已保存连接，右栏表单。点左栏一条是「载入右栏编辑态」
而不是连接，连接要再点一次主按钮；主按钮的文案随改动在「连接」与「保存并连接」
之间跳（ADR-026 的编辑态基线）。用户反馈「不好用」：最常用的动作（连上一台保存
过的机器）要两步，且编辑与连接在同一个界面里纠缠——输个密码主按钮是「连接」，
顺手改个端口就变成「保存并连接」，不看文案不知道这一下会不会写盘。

同时列表里只能用 `user@host:port` 认机器，多台同用户同端口的内网 IP 分不出谁是谁。

## 决策

### 1. 两视图：列表是默认，编辑是显式进入的第二层

- `ConnectModal.view: ConnectView { List, Edit }`，由外壳经 `as_any_mut` 下钻切换
  （与 `forward_form_mut` 同款）。打开弹窗恒落列表（哪怕列表为空：空态引导去
  「新建连接」，行为一致比首次少一步更重要）。
- **列表视图**：全宽一行一条；动作全是行右侧的三个文字按钮——「连接」（强调色，
  这一行的主要动作）直接连、「编辑」进编辑视图、「删除」（低调，悬停转危险色）
  忘掉这条。**行本身不可点**：整行当「连接」按钮的热区太大，一不留神就连出去了；
  显式按钮让每次点击的后果都写在按钮上。底栏「新建连接」（左）/「关闭」（右，
  Esc）。没有输入框，Tab 焦点环为空；回车不认。
- **编辑视图**：原右栏表单单栏铺满。底栏「保存」（主按钮，回车）→ 落盘回列表；
  「保存并连接」→ 落盘、连接、关弹窗；「返回」（Esc）→ 丢弃改动回列表。
  Esc 在这里是「退一层」而不是关弹窗：编辑是列表之下的第二层。点遮罩两视图
  都关弹窗（与既有口径一致）。
- 两视图同宽（0.55 窗宽，520–720），切换不跳；列表高度随条目数长到 0.8 窗高
  封顶后内部滚动，编辑视图定高 0.8（折叠段、切转发类型时尺寸不跳）。

### 2. 主按钮不再随改动切换；基线机制整体移除

「保存」与「保存并连接」都写盘（`upsert` 幂等），不再需要判断「改没改」。
ADR-026 的 `FormBaseline` / `is_dirty` / 输入框逐字监听（`tracked`）/ 转发草稿的
`canonical` 拼法连同其测试一并删除——它们唯一的消费方就是主按钮文案。外壳对
表单实体的 `observe` 保留：开关、折叠、转发草稿增删仍经它触发重渲染。

### 3. 列表直连不经表单：`connect::target_of_saved`

已保存条目直接装配成 `SshTarget`（转发规则、跳板、agent/私钥引用），口令只有
调用方交进来的 `password`（钥匙串回填或刚输入的）。素材不够时报错而不是装出一个
连不上的目标，由外壳决定下一步：

- **仅密码且没记住**（或记住了但钥匙串读不到）：叠一个密码输入框——通用 Dialog
  新增 `secret` 形态（与 `prompt` 同构，输入框遮罩显示；ADR-047 的 prompt 之后第二个
  消费方），确认按钮「连接」，打开即聚焦输入框（ADR-043 §4）。密码只随会话配置
  交出去一次，不落盘。
- **其余缺口**（跳板只有密码认证；密码框确认时留空）：退到编辑视图、载入该条、
  错误显示在表单底部——那里才有口令的输入口，用户补完点「保存并连接」。
- 已知边界：私钥带口令且不走 agent 的条目，列表直连会在认证阶段失败（直连路径
  没有私钥口令的来源）；走「编辑」填口令后「保存并连接」。此前的表单路径同样
  不会强制输口令，不是本次新增的缺口。

### 4. 连接名称

- `SavedConnection.name: Option<String>`，`#[serde(default)]`，旧文件缺字段按「没起名」
  读。名字**不参与条目身份**：身份仍是 host/port/user，同目标改名保存是覆盖。
- 表单「目标」组首位加「名称」字段，可选；trim 后为空即 None（与 ADR-047 的
  `normalize_session_name` 同口径，`ConnectForm::connection_name`）。
- 列表行：上行 `display_name()`（名字，否则 `user@host:port`），下行是目标串
  （起过名时）与素材摘要（`ssh-agent + 私钥 · 需输入 · N 条转发`）。
- **名字成为新建 SSH 标签的初始名**：`open_session_with` 增加 `name` 参数写进
  `Tab.name`（ADR-047 的用户名字，优先级高于 OSC 标题）。SSH 标签不进
  workspace.json（ADR-037），重启后标签与名字一起消失是既有边界；但每次从列表
  连上，侧栏一开就认得出是哪台机器——这正是 ADR-047 动机里「分不出哪一行是
  哪台机器」在 SSH 侧的补全。本地会话传 None 走自动标题。

### 5. 错误放在离补法最近的地方：单字段挂输入框、组合与动作进底栏、钥匙串贴勾选行

落地后两轮试用的反馈：先是「请填写主机」堆在底栏中间，人要自己找是哪个框；改到
标签旁之后，填好主机它还赖着不走——「错误是上次提交的结论」在实践中就是过时信息。
最终口径（2026-10-28 定）：

- **单字段错误挂在输入框本体**：`TextInput` 持有 `error` 状态（`set_error` /
  `error()`），`input::field(tokens, cx, label, input)` 渲染时读它贴在标签右侧
  （红字、与标签同字号 10，`flex_1 + min_w(0)` 就地换行）。校验能力下沉到基础组件
  ——组件只管状态与渲染，**业务方定义有没有错、错什么**；设置表单、转发表单共用
  同一个 `field`，不出错就与原来一模一样。
- **编辑即重算**：会出错的字段（主机/端口/用户/跳板目标/跳板用户）挂输入框监听，
  一动就重跑它自己的校验（`revalidate_field`），错误随值即时消长——填好主机错误
  当场消失，端口敲进 `abc` 当场报、改回数字当场消。转发草稿同理（`revalidate_forward`
  按实体 id 找回下标，增删规则不漂移；三框全空的新草稿不预报错）。校验规则与提交
  时同一套函数，不另写近似。
- **组合校验进底栏**（`Field::Auth`）：「没有认证信息」是 agent + 私钥 + 密码三者合
  起来的结论，不属于任何一个输入框；「新条目勾了记住却没填密码」同类。密码/私钥
  路径一动、agent 或记住开关一拨，底栏的旧结论即过时撤掉，下次提交重算。落盘
  失败这类与字段无关的动作错误（`FormError::global`）也进底栏——它们只能在动作
  发生后出现，补法是重试或修系统，不是改表单。
- **钥匙串读写失败贴在「记住密码」勾选行下**（`Field::RememberPassword`）：失败的是
  这个勾选动作，不是哪个输入框，也不该混进底栏的校验结论里。
- **每轮提交从干净状态重算**：`clear_errors` 先清掉所有输入框、草稿、底栏与勾选行
  的错误，再跑校验；错误只反映最后一次提交 + 此后的编辑重算。
- **错误落在折叠段里时 `fail` 把那段展开**：收起的字段看不见，贴在它旁边的提示也
  跟着看不见。
- 文案：端口错误两处拼法统一为「端口不是 1-65535 的数字：x」；自带字段名、贴到标签旁
  会重复的两条冲突提示去掉前缀；跳板错误去掉调用方拼的「跳板机」前缀。
- 单测 `field_errors_live_on_inputs_and_revalidate_on_edit`：目标三字段各归各家、
  编辑即重算、组合结论进底栏并随相关编辑撤掉、折叠段报错即展开、转发草稿按条
  报错与重算、全局错误只进底栏、回到新建态清空。观察者是效果队列（最外层
  update 结束时冲洗），测试里每个阶段各占一个顶层 update 周期。

## 后果

- 常用路径从「点行载入 → 看主按钮文案 → 点连接」变成点行上的「连接」一步；编辑是
  显式动作，写盘只发生在「保存」/「保存并连接」。
- `ModalActions`：`load_saved`/`connect_only` 换成 `connect_saved`/`edit_saved`/
  `save`/`back`；外壳的 `save_and_connect` 拆成 `persist_form`（落盘，失败已在表单
  底部报错）+ 两个后续（回列表 / `connect_from_form`）。
- connect.rs 删基线机制约 150 行、增列表视图 / 直连装配 / 测试，净增约 100 行；
  app.rs 净增约 125 行（直连、密码框、视图切换）。
- `load_saved` 不再返回焦点句柄：编辑视图进入时一律聚焦主机框（密码框的焦点决策
  属于「载入即连接」的旧语义）。
- 相邻问题（不在本次范围，记录待议）：编辑一条连接并改了 host/port/user 后保存，
  `upsert` 按新身份追加一条、旧条目保留——这是 ADR-010 以来的既有行为，列表优先
  后会更显眼；修法要么 `editing` 下标替换，要么保存时先删旧身份。
- 单测：`connections` 名称往返 / 旧文件兼容 / 改名不新增；`connect` 名称空白归一化、
  `target_of_saved` 素材判定（仅密码 / 空密码 / agent+私钥展开 / 跳板仅密码）、
  键裁决按视图（列表 Esc=Close 回车=None 焦点环空；编辑 回车/Esc=Action）。
  视图切换、密码框叠放、焦点落点与标签初始名按仓库惯例不设单测，手工验收项见
  `docs/context/manual-acceptance.md`。

## 修订（2026-10-28）：「认证素材」更名「认证信息」；钥匙串只在查看与连接确需时读取

- 术语：「认证素材」全部更名为「认证信息」（界面、错误文案、注释与 README），
  含 ssh.rs 里用户可见的「没有可用的认证素材」。
- 钥匙串读取时机收紧为两个（ADR-018 修订）：密码框内右缘内置「显示/隐藏」
  （`TextInput` 的框内开关；已记住密码的条目载入后，空框以一串星号示意已存有
  密码，星号是独立的标识态字段、不掺进输入内容，点「显示」才从钥匙串取回明文），
  与「连接确实需要密码时」（仅密码条目点「连接」、「保存并连接」建立连接前补填）。
  点「编辑」载入不再回填、不碰钥匙串；agent/私钥条目连接也不读。
- 保存不再用空密码覆盖已存的：已记住的条目空框保存即沿用；身份（主机/端口/
  用户）变更时钥匙串条目随迁；取消勾选按旧身份删除。表单侧「记住即有认证信息」、
  载入不回填、「显示/隐藏」只切掩码有单测；钥匙串读写路径按惯例走手工验收。

## 修订（2026-10-28）：保存出口收进连接表单领域；身份变更旧条目让位

- 「相邻问题」销账：编辑改 host/port/user 后保存，旧条目从列表移除
  （`SavedConnections::save(entry, superseded)`，一次落盘）；此前 upsert 按新
  身份追加、旧行残留。旧条目已不在列表时按新身份覆盖/追加，不复活旧条目；
  新身份与既有条目撞上时按覆盖语义合并成一条。
- 保存路径整体下沉 `connect` 领域（保存计划，见 GLOSSARY）：前奏（清错误、
  主机展开、装配校验）、钥匙串分支矩阵与错误落位内化进 `ConnectForm::save`，
  执行分钥匙串步与列表步（`SavePlan::run_keychain` / `apply_to_store`），
  app.rs 的 `persist_form` 只剩编排，`Field` 词汇不再出现在外壳。钥匙串先动、
  成功才落盘的顺序（ADR-018）不变；配置读不出时不再先动钥匙串。
- `SavedConnection::same_identity` 成为身份判定的唯一归属点：查找
  （`find_target`）、就地更新（`replace_forwards`）、覆盖保存（`upsert`）与
  身份迁移判定共用，外壳不再手写三元组比较。
- 单测：保存计划分支矩阵 9 项 + `ZHIMATERM_KEYCHAIN=1` 门控的钥匙串回路
  （connect.rs）；让位、幂等、身份撞车（connections.rs）。手工验收补「改身份
  保存后列表不残留旧行」（`manual-acceptance.md`）。

## 修订（2026-10-29）：认证信息校验移除与连接期密码回退

- 编辑/保存不再拦「没有认证信息」（ADR-018 修订联动）：无静态素材的条目
  可以保存。`target_of_saved` 的素材判定保留——列表直连的密码预填与编辑
  视图回退仍靠它。
- 连接路径新增密码回退：认证走到密码路且手头没有素材时经
  `ControlEvent::PasswordRequired` 询问（临时密码不落盘、三次上限、取消即
  收尾，见 ADR-018 修订）；worker 的 `ConnectAsks` 把信任确认与密码询问
  收进同一等待回路（等待期间继续消化尺寸/关闭）。
- 错误落位变化：`Field::RememberPassword` 退役，钥匙串读写失败进底栏
  （动作级错误）；`Field::Auth` 保留（列表直连的素材缺口仍是它的生产者）。
- e2e：错误口令/叠层失败两用例补「取消询问」的答复臂；新增「无素材经询问
  连上」「三次全错收尾」两个门控用例。

## 修订（2026-10-29，第二批）：保存 = 新建追加、编辑按 id 原位替换；身份不再是键

- `SavedConnection` 增加 `id`（uuid v4；旧存档载入时补发）。列表保存只认
  id：同 id 原位替换，不同 id 一律追加——**同身份条目允许并存**，不再有
  「同身份覆盖」「身份变更旧条目让位」「新身份撞车合并」三种行为。名字
  纯粹是显示标签。
- 动机：身份（host/port/user）同时是列表键与钥匙串键，逼出了整套覆盖/
  迁移逻辑（`upsert`、`save(superseded)`、`SavePlan` 的 `MigrateFrom`/
  `drop_credential`）。钥匙串改按条目 id 挂凭据（ADR-018 修订）后这些
  全部拆除：保存计划只剩「条目 + 手输密码」，凭据随条目 id 走，改主机/
  端口/用户零迁移。
- `SavedConnections::save(entry)` 按 id upsert；`upsert`（身份覆盖）与
  `save(entry, superseded)`（让位）退役。`same_identity` 保留但只服务
  运行中会话与列表的对应关系（`find_target`/`replace_forwards`，ADR-038
  的转发回写）——重复条目下它按首条匹配，是已知的宽松边界。
- 表单新增 `editing_id`：载入编辑时带上，保存成功后指向刚保存的条目
  （新建保存后再次保存是原位替换，不重复追加）；钥匙串「显示/补填」按
  它读取。外壳 `persist_form` 按 id 取旧条目，不再按列表下标。
- 旧存档补发 id 时 `remember_password` 一并作废（那批凭据按身份键存的，
  不再读取，当作都没存过——ADR-018 修订），用户重输一次即落到新键。
- 单测：保存矩阵改为 id 口径（新发 id、原位替换、空框沿用不改钥匙串、
  身份变更零迁移）；connections.rs 覆盖/让位/撞车三个用例退役，换成
  按 id 替换与并存用例、旧存档补发 id 用例。
