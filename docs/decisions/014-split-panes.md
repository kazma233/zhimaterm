# ADR-014:终端分屏（标签内二分嵌套）

状态:已接受(2026-10)

## 背景

MobaXterm 差距分析 P0 #4:「看日志 + 敲命令同屏」是最常见的布局诉求。现状只有
多标签（侧边栏切换），一屏只见一个会话。早前拷问轮已定共识:分屏＝二分嵌套、
每格独立会话、每格自带底栏、比例拖拽、布局不持久化。

## 决策

### 布局模型

- 标签（侧边栏一行）是分屏的容器;单个标签退化为一格时与现状一致。
- 布局是二分嵌套树:叶子是格,内部节点是一次分割(方向:水平并排/垂直堆叠 +
  比例)。任意格可再次分割,深度不限,每标签格数上限 8(防失控,与全局
  会话上限同一精神)。
- 布局不持久化:重启后回到单格(需求 §7 既定边界,窗口状态持久化是另一件事)。

### 格与会话

- 每格是一个独立的 `TerminalView`(独立 worker、独立画面帧、独立焦点),
  格间不共享任何终端状态——与多标签同一并发模型,只是同屏多画。
- **新格的会话类型跟随原格**:SSH 格分屏用同一目标(含内存中的凭据,与原地
  重连同源)新开一条独立连接;本地格分屏新开本地 shell。这是「远端看日志 +
  敲命令」的实际用法;凭据仍只活在内存,随格关闭释放。
- 格自带底栏(`TerminalView` 现有结构不变),只是区域变小;格内网格
  resize 沿用现有 canvas bounds → PTY resize 链路,无需新机制。
- 关闭格:多格标签的每格右上角悬浮 ✕(布局层叠加,不动 `TerminalView`);
  最后剩一格时 ✕ 消失,关标签走侧边栏 ✕。格内会话正常结束时按现有回收
  规则处理:本地格结束即回收,SSH 格保留至用户关闭。

### 交互与键位

- 分割动作从焦点格发起:新格占据分割后的第二格并自动获得焦点,原格保持
  第一格;新会话连接期间焦点格有自己的连接中状态(现有机制)。
- 比例拖拽:分割条 4px 命中区,拖拽期间挂全局鼠标监听(与侧栏调宽同一模式),
  比例夹在 [0.15, 0.85],防止拖出不可用的窄条。
- 键位:macOS `⌘D` 右分屏、`⌘⇧D` 下分屏(iTerm2 惯例);非 macOS
  `ctrl-shift-d` / `ctrl-shift-alt-d`(项目 ctrl-shift 约定,不占用终端
  控制字符)。仅终端网格持有焦点时生效(与复制/粘贴同一上下文)。
- 点击格子即聚焦该格;标签的「当前格」即焦点格,标签标题、R 重连、Enter
  关闭等既有键都作用于焦点格。

## 后果

- `app.rs` 的会话模型从「标签=一个视图」变为「标签=布局树,格=视图」:
  侧边栏列表、回收循环、关闭与激活逻辑改为按标签聚合,聚合细节下沉到
  `panes` 模块(布局树纯逻辑 + 渲染装配),`app.rs` 保持状态机与装配
  (ADR-007 边界)。
- `panes` 模块的布局树是纯逻辑(分割/关闭/比例夹取/布局矩形/命中判定),
  可独立单测;渲染与拖拽装配按项目现状走截图人工验收(无 UI 测试框架)。
- 分屏后每格区域变小,`MAX_SESSIONS=32` 全局上限不变(标签数),每标签
  8 格为硬上限。

## 修订（2026-10-21）

「布局不持久化」被 ADR-037 覆盖：窗口几何与标签/分屏树写入 `workspace.json`，
但只保存本地格——SSH 格在保存时格级剔除，重启后必须显式重连。分屏模型本身
（二分嵌套、每格独立会话、比例夹取、每标签 8 格上限）不变。
