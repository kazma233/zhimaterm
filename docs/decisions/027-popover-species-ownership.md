# ADR-027：侧栏浮层与选择器类 UI 的归属

状态：已接受

## 背景

ADR-007 只给「表单模态」定义了下沉模式（渲染进领域、回调集合回壳）；此后出现的
其他 UI 物种没有归属判据，自然落回外壳。主题选择器（ADR-022）是最典型的一个：
数据与推导链在 `theme/` 领域，但入口行、下拉行、色板、开合状态、bounds 槽位与
浮层装配约 150 行全部住在 app.rs（fb5e34e 引入时未按 007 的精神下沉，也没有
记录豁免理由）。每次给「无表单的浮层 UI」找位置都要重新口头裁决。

## 决策

1. **物种判据**：无输入实体（`Entity<TextInput>` 之类）的浮层/选择器，归属是
   **领域模块内的普通结构体 + 渲染函数**——状态与渲染单点在领域视图文件，
   外壳只留装配调用与语义动作回调。有输入实体的才按 ADR-026 实体化。
2. **入口行与浮层锚是同一概念**：入口行的 bounds 槽（渲染帧写入、浮层按它
   定位）随入口一起住在领域视图，不留在壳。
3. **回调集合保持语义动作粒度**：`theme::picker::PickerActions { toggle, pick,
   close }`，与 ModalActions / AreaActions 同一模式——渲染层不接触应用实体，
   依赖保持单向（ADR-007）。
4. **编排留壳**（与 ADR-026 决策 5 同一边界）：主题的生效（`set_theme` + 推导）、
   扇出方案到全部会话视图、写设置落盘，资源都在外壳唯一所有者手里，
   `apply_theme` / `pick_theme` 留在 app.rs，picker 只发 `pick(name)` 动作。
5. **互斥另议**：浮层与模态互斥的收敛（手工全对全清空 → 「当前模态」单概念）
   不在本 ADR 范围，随模态互斥收敛统一落地；此前主题下拉不参与互斥的现状
   维持不变。

## 后果

- 主题选择器的全部知识（开合、锚点、入口/行/色板渲染、当前项判定）单点在
  `theme/picker.rs`（219 行，含状态机单测）；app.rs 净减约 110 行，只剩
  `apply_theme` / `pick_theme` 两个编排方法与装配一行。
- 新的浮层物种（右键菜单已有 ADR-023 归属；未来的侧栏浮层、非表单选择模态）
  按判据 1 找位置，不再落回外壳；`settings::form` 的下拉属于表单内部，不适用
  本判据。
- 测试面如实收窄：本 ADR 带来的主要是 locality，`ThemePicker` 只补开合状态机
  单测；渲染函数返回 gpui 元素，不做内容断言；交互契约（连点不收起、点外
  收起、落盘失败文案）维持手工验收。

## 验证

- `cargo test`：212 项通过（新增 picker 状态机 1 项），存量 ConPTY 冒烟的环境
  抖动除外。
- 手工冒烟：侧栏底部点开主题下拉 → 连点几项比对观感（每项立即切换、下拉不
  收起）→ 点击下拉之外收起 → 切换后重启恢复上次保存的主题。

## 修订（2026-10-18）

决策 5 预告的「浮层与模态互斥的收敛」已落地：外壳以 `modal: Option<Modal>`
单点管理互斥（枚举携带模态数据，open_modal / close_modal 是唯一出入口），
打开任何模态时收起主题下拉（等价它的「点外部收起」契约）；主题下拉自身
仍不是模态——「连点不收起」的 ADR-022 契约不变。
