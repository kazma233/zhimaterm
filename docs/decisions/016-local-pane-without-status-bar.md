# ADR-016:本地格不设底栏(启动与故障信息进网格中央)

状态:已接受(2026-10;2026-10 修订:见文末注记)

## 背景

每格底栏(ADR-005/011/014 之后的界面骨架)同时承担三类内容:常驻信息(远端监控、
连接过程、结束原因与自动重连倒计时)、功能入口(SFTP、转发开关)与操作回执
(复制结果、程序写剪贴板、打开链接)。前两类只有远端会话会产生——本地格没有
监控、没有 SFTP、没有转发,也没有可重连的目标。

盘点本地格底栏实际会出现的内容,真正有信息量的只有一条:**终端起不来时的失败
原因**(创建本地 PTY 失败 / 在 PTY 中启动 Shell 失败 / 会话内部错误),它在界面
别处没有落点(侧栏只标「已结束」)。其余都可去:

- 启动提示与网格里的「正在启动本地 Shell…」重复;
- 操作回执是弱信息,而且不会自动消失——状态文案只在认证成功时清一次,没有定时器,
  最后一条回执会一直挂在底栏,变成一条陈旧行。

健康运行中的本地格,底栏本就是一条空横条(运行中不占文案),占着 30px 高度。

## 决策

### 本地格不渲染底栏

本地格的终端区域直接顶到窗口下缘,网格由此多约一行。判定按会话类型,本地格永远
不画底栏,不做「没有内容就隐藏」:那会让网格高度随状态来去反复变化,每次复制、点开
链接都触发一次 PTY resize,反而引入布局抖动。

### 「起不来终端」的信息走网格中央

本地格的启动中、启动失败、终端不可写入统一在终端区域中央显示:

- 启动中:「正在启动本地 Shell…」;
- 启动失败(本地 PTY/Shell 启动失败、会话内部错误):失败原因 + 「Enter 关闭」;
- 终端不可写入:该文案本身。

本地 shell 正常退出不在此列——本地格退出即回收(ADR-005),用户看不到结束态。

网格中央只为本地格服务:远端格的一切状态都在底栏,包括连接中(带已等待秒数,
区分"慢"与"死")。这块中央提示原先也承担远端的连接中提示,现收回,远端格从
连接中到失败到监控,始终在同一行上推进,不在两个位置间跳。

### 本地格不套用连接看门狗

界面兜底的连接看门狗(传输层 45s×2 预算之外仍未出画面即判超时)只管远端握手。
本地没有握手与传输预算,启动失败由 PTY/Shell 启动错误确定性地报出(Failed);
看门狗一旦在本地误判,会把一个可能活着的会话标成结束态,而 Enter 会关掉这一格,
比少一个兜底更糟。

### 本地格不产生操作回执

复制结果、程序写剪贴板、打开链接三类回执只写远端格的底栏;本地格不做提示(macOS
常规行为本就没有复制提示,本地程序写剪贴板也不跨越信任边界)。

### 远端格的行为

底栏、监控、SFTP/转发开关、结束原因、自动重连倒计时与 R/Esc/Enter 键位全部保持
原样。唯一变化是连接中那句话:它原先同时出现在底栏与网格里,现在只由底栏按秒数
现算(`StatusBar::Connecting`),不再有第二份来源;主机密钥确认的结果也不写状态
文案了(确认后秒数继续走,拒绝的原因由 Failed 给出)。

## 后果

- `TerminalView` 增加会话类型(本地/远端)的显式判定,渲染尾部据此决定是否画底栏;
  判定跟随分屏新格(`split_target` 复制本格类型)。
- 网格尺寸计算不用改:`view::grid_size` 按实际 bounds 算,底栏消失后自动多一行并
  触发一次 resize。本地 shell 启动期本就会 resize 一次,不新增抖动路径。
- 回执文案在本地格不再产生,远端格行为不变,同一动作在两个格的提示与否会有差异,
  这是本决策的直接代价。
- 混合分屏(本地格与远端格并排)两边网格高度差一条底栏,是每格独立底栏方案的直接
  后果,接受。
- 中央提示的位置与内容可纯函数化,单测覆盖「哪种状态显示什么」;观感仍需 UI 预览
  钩子加截图人工确认。
- 需求规格 §3.3 的界面骨架条目与 README 同步更新。

## 修订注记(2026-10,ADR-028)

「前两类只有远端会话会产生——本地格没有监控、没有 SFTP、没有转发」这一前提,
监控部分已被 ADR-028 修订:本地默认 Shell 格现在有进程探针侧边栏(进程树 + LISTEN
端口)。本决策的布局结论部分修订——本地默认 Shell 格现在有一条底栏,但只承载
探针入口(右端「进程」开关),信息区留空:启动与故障信息仍走网格中央,探针数据
在右侧停靠面板。展开面板时终端让宽属用户显式开合,与底栏随状态来去抖动是两回事。
WSL 格仍无探针也无底栏(ADR-028)。
