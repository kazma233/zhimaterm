# ADR-009：文本输入组件

状态：已接受

## 背景

表单里的输入框需要完整的编辑体验：选区与扩选、复制剪切粘贴、撤销重做、双击选词、
拖选、多行文本。此前的单行实现只有“插字符、删字符、移动光标”，编辑长文本
（私钥路径、口令、多行内容）很别扭；同时密码字段必须掩码，而掩码不能破坏
已有的选区、光标与鼠标命中逻辑。

## 决策

- 组件分层：`core.rs` 持有全部编辑状态与逻辑（`TextCore`，与实体无关，
  notify 由外层实体负责）；`TextWidget` 提供构造配置、setter 与渲染骨架；
  `ActionWiring` 是模块内的键位/鼠标接线；`TextElement` 是泛型绘制元素
  （整形、光标/选区/IME 下划线、滚动）。组件对外只有构造（单/多行、掩码、
  字体）、`text`/`set_text`/`clear` 与 `focus_handle`。
- 索引空间是内容的 UTF-8 字节偏移，只在 IME 协议边界换算 UTF-16；
  IME 组合文本（marked text）直接写在内容里并记录标记区间，提交与取消
  走同一条替换路径。
- 编辑键位由 `ui::input::bindings()` 声明、随应用键位在 `main` 一起注册：
  输入框持有焦点时按键被输入框消费；焦点在其他位置时，没有处理器接收的动作
  回落给按键路径（终端 ↑ 仍是历史命令、⌘V 仍是终端粘贴）。
- 掩码不改变索引空间：显示文本按**同 UTF-8 字节长度**一对一替换
  （`*`/`·`/`•`/`🔒` 对应 1/2/3/4 字节，换行保留），字节偏移与明文全等，
  因此选区、光标、鼠标命中、IME 协议全部复用同一套索引，不需要任何换算；
  掩码字段复制/剪切不写剪贴板，明文只留在输入框自身的编辑状态里。
- 单行框的粘贴清洗：换行丢掉（口令尾部不能静默多出空格）、制表符变空格、
  其余控制字符丢掉；多行框原样保留。
- 单行框回车不消费（`cx.propagate()`），表单的回车提交在应用层
  （`app::handle_key_down`）。
- 多行能力与滚动指示条（`ui/scrollbar`）随组件一并提供，供后续大段文本
  场景（SSH 配置等）使用。

## 后果

- 表单获得完整编辑能力，组件对外面收窄。
- 掩码与粘贴清洗有独立单测；布局导航决策（折行、goal column、词边界）
  用假布局做无头验证。
- `set_disabled`/`set_read_only`/`set_on_change`/`set_on_press` 与
  `new_multiline` 暂无消费方（模块级 `allow(dead_code)` 注明），是锁定输入、
  结果展示、实时过滤、下拉展开等后续功能的预留入口。

## 验证

- `cargo test`：掩码字节对齐、单行粘贴清洗、折行/导航/词边界用例。
- 真实 GUI：粘贴、⌘A 全选、跨字段 ⌘C/⌘V、⌘Z 撤销、双击选词、密码掩码、
  回车提交表单、Esc 关闭；终端内 ⌘V/回车/↑ 不受绑定影响。

## 附记（2026-10-18）：键位表的平台配对构造

`bindings()` 原先对平台差异逐行贴 cfg 属性（38 个）——那种写法漏写一侧不报错，
只会让该平台静默丢键（与 ADR-021 附记的 cfg 分叉教训同源，但更隐蔽：枚举漏臂
至少编译失败，键位漏配直接上线）。改为 [`platform_binding`]（动作, macOS 拼写,
其余平台拼写）的配对构造：两侧拼写强制出现在相邻一行，漏配在结构上不可能；
单侧键位（macOS Home/End 别名、Windows 传统三键）对应侧传 `None`。

两个有意的取舍：

- **两侧拼写都构造、运行时只取当前侧**——`KeyBinding::new` 对非法拼写 panic，
  因此任一侧的拼写错误在所有平台的启动期暴露，不潜伏到对应平台才发作。
- **配对是数据不是类型**：与 SHORTCUTS 表的 `ShortcutSpec { mac, other }` 同款，
  两张表动作域不同（编辑键 vs 应用快捷键），不为统一再抽一层。

验收：重构前后按平台展开的 `(keystroke → action)` 集合逐一相等（macOS 33 条、
其余平台 35 条，diff 为空）；新增 `bindings_have_no_duplicate_keystroke` 护栏
（重复拼写几乎总是配对写错的症状）。
