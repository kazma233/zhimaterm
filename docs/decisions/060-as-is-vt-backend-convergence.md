# ADR-060：VT 后端原样接入与双后端收敛

状态：已接受（2026-11-21）

## 背景

emoji 字形簇宽度的表格错位催生了三后端并存（ADR-050/051）：alacritty
（默认，逐码点口径）、termwiz（本仓屏幕模型 + 适配层簇回写）、ghostty
（核心原生簇口径）。2026-11 的上游与社区调研（
[vt-upstream-landscape](../context/vt-upstream-landscape.md)）确认三件事：

1. alacritty 上游对簇宽度是**立场性不修**（#3975：wcwidth 契约立场 +
   shaping 成本 + 维护者无需求，P-low 挂五年余），近一年核心语义零变化
   ——「等上游跟进」不是可依赖的路径。
2. 簇口径 vs wcwidth 的分裂是生态常态而非本仓遭遇的孤立缺陷：wezterm
   #4223 的正反方碰撞、kitty/ghostty/iTerm2/Windows Terminal 的簇阵营
   与 DECRQM 2027 检测机制并存。
3. libghostty-vt 1.0（2026-11-06）C ABI 语义化稳定、JetBrains 全系终端
   采用、CI 实测矩阵含 Windows——ghostty 后端作为簇口径唯一承载的可行性
   显著增强（本仓已 pin 1.0.0）。

据此复核现状：同一份簇语义在仓内有 1.5 份实现（ghostty 原生 + termwiz
回写），适配层长出三类「让后端看起来一样」的兼容逻辑。决策：**只接入
原样的 VT，不做兜底和兼容修复**——AGENTS.md 设计原则（少写补丁、无真实
契约支持不加 fallback）明确约束 VT 接入层。

## 决策

### 1. 原样接入原则（术语见 GLOSSARY「原样接入」）

- VT 核心按上游原样接入；适配层职责只有「字节 → 网格」的契约桥接：
  FFI 绑定、快照/物化形状对接、查询应答的路由——不做桥就接不进来的部分。
- 后端间的上游差异（宽度口径、DA1 声明、应答结尾符……）**原样暴露**，
  不入适配层抹平；差异在 ADR-050/051 分歧表记账，不在代码里修齐。
- 有真实契约支持的机制不算兜底，保留：同步输出渲染端定格（mode 2026
  的可见语义，ADR-051 §2）；`set_theme_defaults` / `set_cell_pixels`
  （核心自答的机制输入，ADR-051 §2.1 复核结论）。

### 2. 终态：双后端

- **alacritty（原样 wcwidth/逐码点）+ ghostty（原样簇口径）**，对冲生态
  两派；termwiz 后端**退役**——其本仓屏幕模型与簇回写正是本原则要消除的
  偏离，SGR 21/真实制表位/跨列增宽三处「更正确」口径随之退役，接受各
  上游原样。
- 默认后端切 ghostty（修订 ADR-050「默认 alacritty」与 ADR-051「默认
  候选」的口径）。

### 3. 分步执行

| 步 | 内容 | 闸门 |
|---|---|---|
| 1 砍兼容层 | a. 删 termwiz 簇回写（`join_cluster`、内嵌 emoji-variation-sequences 基表、`cluster_width` 测试），termwiz 后端暂存续并失去簇正确性；b. 删 ghostty DA1 对齐，核心按默认自报，程序按 DA1 分支的差异显形；c. 废除应答单点格式化与固定 ST 统一（ADR-051 §2.1），应答字节回归各后端原样（alacritty 按查询结尾镜像、ghostty 直通核心应答），路由保留；d. 契约/差分测试口径同步：一致断言改为各后端原样断言或结构不变量 | 每项先有失败复现；收尾检查三项全绿 |
| 2 真实使用验证 | ghostty 后端在 Windows/Linux 日常使用验证（表格对齐、TUI、IME、SSH 长尾；上游 CI 实测 ≠ 日常使用） | 记录进 platform-verification.md |
| 3 收敛 | 默认切 ghostty；删除 termwiz 后端与专属测试、分歧表相关行（约 −2000 行），设置项后端枚举收窄 | 以步骤 2 通过为前置；未通过则默认维持 alacritty，termwiz 去留重新答辩 |

> 步骤 1 已执行（2026-11-21）：簇回写 / DA1 对齐 / 应答统一三类兼容层
> 删除，契约测试改分后端原样断言。实测补充：ghostty 核心的颜色应答同样
> 按查询结尾镜像（非固定 ST）——三后端中仅 termwiz（解析器不外露结尾符）
> 固定 ST，口径已写入 GLOSSARY「查询应答」。

### 4. 已知接受的后果

- 非簇后端（alacritty，及步骤 1 后的 termwiz）上 emoji 表格错位回归——
  上游原样行为，不修；簇正确性由 ghostty 单腿承担，上游回归时错误显形
  而非兜底掩盖。
- 步骤 1~3 之间，同一程序在不同后端的可见差异（DA1 分支、应答结尾符）
  显形；用户经设置自选后端并承担差异。
- ADR-050 §4「等上游跟进后移除本条分歧」的欠账表述失效：上游为立场性
  不修，收敛不再以为上游条件。

## 后果

- 工作区移除 termwiz 依赖面；契约/差分测试从三后端降到两后端。
- 分歧表瘦身：簇宽度、DA1、应答结尾符等行从「修齐」改「上游原样」记账。
- ADR-050 §5/§4 相关行、ADR-051 §2（DA1）/§2.1 随各步执行在文内修订
  标注；GLOSSARY「查询应答」随步骤 1c 改写。
- 本 ADR 只立口径与计划，行为变更在各步实施时进行，每步独立成提交
  （`refactor(terminal): …`）。

## 验证

- 步骤 1：砍除前先写失败复现（如 DA1 分后端断言、应答结尾符分后端
  断言），改后契约/差分测试按新口径全绿 + 收尾检查三项全绿。
- 步骤 2：验证清单与记录归 platform-verification.md。
- 步骤 3：删除后 `cargo test --workspace` 全绿，设置后端枚举收窄为
  alacritty/ghostty。
