# ADR-002：SSH 信任、凭据与 SFTP 文件安全

状态：已接受

## 背景

ZhimaTerm 管理远程 Shell 和远端文件。主机身份验证、密码存储和覆盖写入属于高影响操作；默认宽松策略会使中间人攻击、凭据泄露或非预期文件覆盖难以被发现和追溯。

标准 SFTP 的 rename 语义不足以保证所有服务端都能原子覆盖既有目标。将“同目录临时文件”直接等同于“安全替换”会在不支持相应扩展的服务端上破坏既有文件。

## 决策

### SSH 信任

- 使用应用配置目录中受管理的 `known_hosts` 进行严格校验；首版不读取或修改用户的 `~/.ssh/known_hosts`。
- 主机记录的唯一键是用户输入的目标主机名与端口，并保存 host key 算法、原始公钥和 SHA-256 指纹。
- 未知主机密钥必须显示算法和 SHA-256 指纹，经用户一次明确确认后才记录。
- 已记录主机的指纹变化先拒绝直连并弹确认浮层，用户核验新指纹并显式选择
  「信任新密钥」后按唯一键替换记录再继续连接；取消则中止并显示错误。
  绝不静默接受或自动更新。（修订记录：原条款为「一律中止连接并显示错误，
  不提供静默接受或自动更新」，2026-10 按用户决策修订——中止留档没有出路，
  服务器重装后用户只能手工改文件；改为显式确认后替换，防中间人的本质
  ——不接受无确认的降级——不变。确认浮层不展示旧指纹：记录文件只存公钥
  本体，展示需另行引入哈希依赖，而核验动作本就应当拿新指纹对照服务器。）

### 凭据

- 密码默认仅存在于本次连接的运行时内存。
- 只有用户显式选择“记住密码”时，才将密码写入操作系统安全凭据存储。
  （修订记录：2026-10 由 [ADR-018](018-remember-password.md) 兑现——
  条目键与保存的连接同构，写入口只有保存连接一处，读在载入表单时回填、
  读不到即回退手输，忘掉连接时联动删除。）
- 应用配置只保存安全存储中的凭据引用，绝不保存密码明文。
- 私钥由用户在认证时选择文件；应用不持久化私钥路径、私钥内容或私钥口令。

#### 实现记录（SSH 交互 shell 第一版）

- 受管记录文件是 `<应用配置目录>/known_hosts`，用 libssh2 的 OpenSSH 格式读写；
  记录里保存主机名与端口、算法与原始公钥，`SHA256:` 指纹由保存的公钥推导（不再冗余存一份）。
- 非标准端口按 OpenSSH 的 `[host]:port` 形式记录，避免同名主机的不同端口互相覆盖。
- **落盘串行化（2026-10-22 兑现评审发现的技术债）**：known_hosts 是跨连接、跨进程
  共享的持久状态，而每个连接各持一份打开时的快照——并发信任主机时整文件写回，
  后写者会覆盖先写者的条目。record/forget 现在都经 `known_hosts.lock` 文件锁串行
  （std `File::lock`，flock / LockFileEx 的 per-handle 语义同时管住本进程的多个
  Store 实例与其他进程实例）；record 在锁内以最新文件为底本合并、同键重复为幂等
  空操作，并与 forget 同款 tmp+rename 原子替换——此前 record 是直接覆盖写，
  并发读者可能读到半截文件。进程内合并、幂等与锁互斥有单测守住；跨进程实机
  并发无确定性测试（两进程时序编排脆），依赖锁语义本身。
- 私钥若存在同目录的 `<私钥>.pub` 会一并交给 libssh2：部分私钥格式自身不带公钥部分。
- 密码认证与私钥口令只存在于连接期的内存里；第一版没有"记住密码"，也没有安全存储适配器，
  因此 `SshAuth` 里不存在持久化字段。
- 界面层只在显式动作下泄露本机影响：未知主机要用户按指纹确认一次；已记录主机直接放行。
- 应用不扫描 `~/.ssh/id_*`、不做默认密钥发现：与"私钥由用户在认证时选择"一致，
  也让"用了哪把钥匙"始终可见。要不要支持默认密钥目录，属于需要单独决定的策略。
- 凭据在认证结束后就地覆写再释放（`SshAuth` 的 `Drop` 调用 `wipe`）：口令不因为"还挂在
  会话线程栈上"而多活一整个会话。

### SFTP 写入与破坏性操作

- 覆盖上传和下载目标前要求用户确认。
- 重命名不得静默覆盖。
- 上传写入远端同目录临时文件，完成后以覆盖 rename 提交；rename 报错时**回退为直接
  写入目标**（打开目标并截断）。该回退路径上放弃「中断不损坏既有目标」的保证——
  传输中断时既有目标可能留下部分新内容。**删除旧目标再 rename 始终禁止**：两步
  之间失败会把文件彻底丢掉，比部分覆盖更糟。（修订记录：原条款为「不支持时目标
  已存在即失败」，由 [ADR-005](005-sftp-subsystem-and-session-lifecycle.md) 按用户决策修订。）
- **覆盖提交的原子性受依赖绑定限制（实现期核实）**：ssh2-rs 0.9.6 的
  `Sftp::rename(OVERWRITE | NATIVE)` 走 libssh2 的普通 `SSH_FXP_RENAME`，标志只在
  SFTP 协议 v5+ 发给服务端；posix-rename@openssh.com 扩展在 libssh2 里是另一个
  ssh2-rs 未绑定的函数。因此：SFTP v5+ 服务端原子覆盖；OpenSSH v3（最常见）上
  普通 rename 目标已存在即失败，**确认覆盖的上传一律走回退直写**（结果正确，
  非原子、双倍传输）。新文件上传的 `rename`（无 OVERWRITE）在 OpenSSH 上直接
  成功，是原子提交。若未来需要覆盖场景也原子，需直调
  `libssh2_sftp_posix_rename_ex`（unsafe extern，约百行）或更换 SSH 依赖，属独立决策。
- 下载写入本地同目录临时文件，再使用平台原子替换能力提交；无法保证原子替换时必须失败并报告原因。
- 传输失败或取消后尝试清理本次创建的临时文件；清理失败时，终态必须包含临时文件路径。
- 首版支持取消并将网络中断视为失败，不实现自动重试和断点续传。
- 递归删除非空目录**实现**（原条款为「默认不实现」，由 ADR-005 修订）：SFTP 没有
  递归原语，由客户端 DFS 完成（readdir → 文件与符号链接 unlink，符号链接不跟随 →
  目录递归 → rmdir），做成任务型操作（有进度、可取消、分轮推进，不独占会话）；
  非空目录删除前必须有一次可见确认。

### OSC 52（程序写/读系统剪贴板）

- 采用核心的保守默认 `Osc52::OnlyCopy`：允许前台程序**写入**剪贴板，拒绝程序**读取**剪贴板。
  终端程序（tmux、neovim 等）用写入把选择内容交给系统剪贴板，是常规交互；读取则会让任何程序
  （在 SSH 会话里是远端）拿到本地剪贴板内容。
- 策略在代码中显式写出，不依赖 `Config::default()` 的隐式取值，便于审计。
- **SSH 会话启用 OSC 52 之前必须重新评估**：远端输出不可信，写入会把远端内容放进本地剪贴板。
- 决定（SSH 交互 shell 第一版）：SSH 会话沿用同一策略（允许程序写剪贴板），
  代价由"来源标签常驻侧栏会话行"承担——用户能持续看到当前会话是本地还是远端。
  该决策与是否需要大小上限一起，在实现 SSH 会话时单独确认，并记录结论。
- 残余风险已知且不在此处缓解：核心在发出事件前已完成 base64 解码，因此超大的 OSC 52
  写请求造成的瞬时内存占用无法在事件处理层拦下。

### 超链接（OSC 8）

- 允许程序把一段文本标记为链接；**打开动作必须由用户显式触发**：macOS 用 ⌘ 点击、
  其他平台用 Ctrl 点击。单击仍然属于终端自身的选区/鼠标上报手势。
- 该点击不转发给前台程序（既不选区也不上报），避免一次点击既打开链接又触发程序行为。
- 只打开系统能处理的目标，不自行下载或执行内容。
- **SSH 会话启用前必须重新评估**：远端可以把任意文本标成链接，诱导用户打开本地或网络目标。
- 决定（SSH 交互 shell 第一版）：SSH 会话沿用同一策略。链接打开本来就必须是 ⌘/Ctrl + 点击，
  已经是一次显式用户动作；来源标签同时提示输出不可信。
  与 OSC 52 相同，届时需要确认是否需要 scheme 白名单与打开前确认。

### 纯文本 URL 识别（hints，OSC 8 之外的补充决定）

- 终端输出的普通文本里只有 **scheme 白名单 http/https/ftp** 的 URL 被识别为链接，
  走与 OSC 8 完全相同的交互（悬停下划线 + 手型、⌘/Ctrl + 点击打开）。
  `file://` 不识别（防止诱导打开本地目标），裸域名不识别（误报率高、且打开时
  补全 scheme 的行为不透明）；识别在快照构建时按行进行，无持久状态。
- 尾部句子标点（`. , ; : ! ?` 与对应中文标点）剥除后才算链接；闭括号只在打破
  配对时剥，`…/Foo_(bar)` 这类合法尾括号保留。
- 显式 OSC 8 优先于文本识别：程序标记的 uri 是权威意图，字面上是 URL 的文本按标记打开。
- 已知局限：只在单行内识别，折行的长 URL 各行各自成链（第一版取舍，跨行识别
  需要行级之上的拼接，待真实需求出现再评估）。

## 后果

- 首次连接会增加一次用户确认步骤，主机密钥变更会阻断工作流，但可防止无提示的信任降级。
- “记住密码”依赖各目标平台的安全存储适配器；适配器不可用时，应禁用该选项并保留运行时登录能力。
- 临时文件策略降低中断时损坏既有文件的概率；确认覆盖的上传在 OpenSSH v3 上走
  回退直接写入（绑定限制，见上文），既有目标在该回退路径上不再受「不部分损坏」
  保护（用户已接受该取舍）。
- 递归删除是破坏性且不可恢复的操作，靠删除前的可见确认与任务取消兜底。
- 不支持断点续传可保持任务状态机与错误语义简单；后续若加入，必须重新定义临时文件命名、偏移校验、冲突和幂等规则。

## 验证

- 未知主机、已知主机和指纹变化三种连接场景均有集成测试；测试覆盖主机名、端口和 host key 算法共同构成的记录匹配。
- 配置文件和应用日志中不出现密码或私钥内容。
- 取消、断线、权限拒绝、空间不足、目标冲突和 rename 冲突都能产生明确终态。
- 传输失败后，走临时文件路径的目标不被部分内容覆盖；临时文件按定义清理或保留并说明原因。
- 覆盖提交的两条路径都有测试：rename 成功路径由内存桩单测覆盖（断言走覆盖 rename
  且临时文件消失）；回退路径由桩（模拟拒绝覆盖 rename）与真实 sshd e2e 共同覆盖。
- 递归删除：符号链接被删除而非跟随；取消后剩余目录结构可读、已删条目如实计入终态。

## 保存的连接（补充决定）

界面需要"下次直接选上次保存的"，这就把一份 SSH 元数据写到了磁盘上，因此补充以下约束：

- **只存能重建连接的字段**：主机、端口、用户、认证素材引用（agent 开关、私钥路径）、
  agent 转发开关与转发规则。（字段清单原为「认证方式、私钥路径」，由
  [ADR-010](010-auth-credentials-stack.md) 起扩充：认证素材叠加、转发规则与 agent 转发开关。）
  口令与私钥口令一律不落盘，需要口令的方式在连接时由用户重新输入
  （只有密码素材的条目点开后预填表单、焦点落到密码框）。
  这条约束用测试盯住：文件里不允许出现 `password` / `passphrase` / `secret` / `token` 这类字段名。
- **位置**：`<config_dir>/connections.json`，与主机密钥记录同目录（macOS 为
  `~/Library/Application Support/Zhimaterm`，`ZHIMATERM_CONFIG_DIR` 可覆盖）。
- **写入是原子的**：先写 `.json.tmp` 再 rename，读到的要么是旧内容、要么是新内容。
- **读不出来就不写**：解析失败时应用进入"保存的连接不可用"状态，在模态框顶部说明原因并拒绝保存。
  否则下一次保存会把读不出来的文件覆盖成空列表，用户存过的连接会真的消失。
- **同一目标覆盖**：`用户@主机:端口` 相同的条目在保存时替换，而不是堆积重复项。
- 删除是一条独立动作（列表里的 ✕）：能存就得能删，否则写错的条目会一直留着；
  点删除按钮不会顺带触发该行的"直接连接"。
