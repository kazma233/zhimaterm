# ADR-017:会话输出日志(只记输出,会话级开关)

状态:已接受(2026-10)

## 背景

P1 #6(`docs/context/mobaxterm-gap-and-priorities.md`):排查留档、事后回溯,
运维/后端高频。现状只有滚动历史(内存里、会话关了就没)与 `replay.rs`(测试
工具),没有落盘的录制。

安全边界沿用 ADR-002:凭据不落盘。日志 ADR 必须写清落盘位置、格式与
「不写什么」。

## 决策

### 落盘位置

应用配置目录下的 `logs/` 子目录(macOS
`~/Library/Application Support/Zhimaterm/logs/`,Windows
`AppData/Roaming/Zhimaterm/logs/`,Linux `${XDG_CONFIG_HOME:-~/.config}/zhimaterm/logs/`),
与主机密钥记录、保存的连接同源,零配置。

文件名 `<本地时间 YYYYMMDD-HHMMSS>_<来源标签净化>.log`,来源标签是侧栏
同款的 `user@host:port`(端口分隔符等文件系统不利字符净化为 `_`)。
文件以追加模式打开:同一秒同目标的两个格(如分屏)写进同一文件,靠首尾
标记区分,不覆盖、不加锁互斥。

### 只记输出,不记输入

记录点在会话 worker 的终端模拟之后:输出字节先进终端模型,转录模型
渲染完成的行(修订前记录原始字节流,见下节修订记录)。输入路径(按键、
粘贴、IME)完全不接触日志。

两个由此推出的边界要写明预期:

- **TTY 回显会落盘**:输入经远端 tty 驱动回显后属于输出,日志里能看到
  敲过的命令——这与在终端里看到的一致,不是"偷记输入"。
- **无回显的输入不落盘**:密码提示(ssh 客户端、sudo)没有回显,不会
  出现在日志里。这是"只记输出"方案的安全性质。

终端查询应答(DA1/DSR 等)是应用写向 PTY 的字节,不属于程序输出,不记;
OSC 标题、颜色与鼠标序列被终端模型消费,不产生可见文本,同样不进日志。

### 格式:首尾标记 + 渲染后的行文本

```
==== 会话开始 2026-10-15 15:30:12 deploy@web-1:22 ====
<终端渲染后的行文本,一行一条,折行已接续>
==== 会话结束 2026-10-15 15:41:00 ====
```

- 正文是**终端渲染后的行文本**(UTF-8):屏幕上看到什么,日志里就是
  什么。网格行折行(WRAPLINE)接续成逻辑行;`\r` 重绘只记最终状态
  (进度条类输出收敛为一行);CJK 与组合字符按模型内的文本还原;
  行尾空白裁掉。会话收尾时把仍留在屏幕上的行冲进日志(通常是尾部输出)。
- **备用屏(全屏程序)不记录**:vim/htop 这类程序的界面画在备用屏上,
  不产生主网格滚动历史,天然不进日志;其中执行产生的命令输出(回到主屏
  后滚动)照常记录。
- 开始标记在 worker 入口写:每次 spawn 尝试(初次连接、每次重连)各写
  一对,重连在同一文件里追加新的一对,文件按格(视图)而不是按连接分配。
- 结束标记在 spawn 包装器的所有出口写:正常结束、连接失败(`Err`)、
  worker panic 三条路都收口到那里,不会漏掉失败尝试的右边界。
- 正文不做逐行时间戳:避免刷屏输出成倍膨胀,排查时按首尾标记与会话上下文
  定位;需要精确到行的时间轴时再加独立选项。
- 标记行自带时间戳(本地时间)与来源,文件被单独拷走也能自述来历。

> 修订记录(2026-10-15,用户验收反馈):正文原为「原始输出字节,原样追加,
> 含转义序列与 `\r`」,即 `script(1)` 的 typescript 口径。验收结论是原始流
> 对主用例(事后翻看、grep)不可读——vim/less 默认按字面显示控制字符,
> `\r` 重绘与颜色序列成噪声。改为终端模型渲染后的行文本(MobaXterm 口径),
> 代价:失去字节级忠实,不能再用 `less -R` 重放颜色;resize 引发的历史
> 重排可能留下少量行重复或缺口(写出游标按当前历史长度钳制,不回抄)。

### 开关粒度:会话级运行时开关,默认关

- 开关在 SSH 格底栏的「记录」入口(记录模态),经 `recorder::set_logging`
  切换:只作用于本格本会话,不写进任何设置或连接存储;暂停与恢复写同一
  文件,各自落标记。
- (2026-10-24 修订,用户决策)初版的连接级开关已整体废弃:连接表单 chip、
  `SavedConnection`/`SshTarget` 的 `logging` 字段、建格时按目标自动开启
  全部移除——「这条连接要不要记录」由用户在会话里现决定,不预设。旧存档
  里的 `logging` 键读取时按未知键忽略,下次保存自然消失。分屏新格一律
  不带记录,要记各自再开。
- 本地会话不提供开关、不落日志:排查留档的对象是远端会话,本地 Shell
  的等价能力是 shell 重定向,不值得为它多一条配置路径。

### 故障行为:日志绝不拖垮会话

- 文件创建失败(目录权限、磁盘满):该格不开日志,侧栏会话行亮起
  「⚠ 日志」标记,连接照常进行。
- 中途写失败(磁盘满、文件被删后重建等):停止记录,经
  `ControlEvent::LoggingStopped` 上报,侧栏同样亮标记;原因文本走状态
  文案(回执通道)。
- 主循环之前就提前失败的写错误(如 begin 首写失败且连接随即失败)由
  spawn 包装器的收尾检查补报,同一个事件、同一份停写语义。
- 可见性取舍:标记持续亮到本格结束——日志坏了不会自愈,不做看清即清
  (与响铃不同);原因文本在监控常驻时不可见(与既有操作回执同通道,
  见 ADR-016 的通道归属)。文件里已写的内容保留,缺右边界标记。
- 写日志的任何错误都不影响终端会话本身:worker 只追加字节,不因日志
  失败而失败。

### 所有权与并发

`SessionLog` 的归属与传递按 ADR-045 收进全局记录门面（2026-10-22 修订）：
`TerminalView` 建格时经 `recorder::attach_log` 注册本格条目（sink 是
`Arc<Mutex<Option<SessionLog>>>`），worker 线程入口按格 id 绑定到线程
局部，之后埋点无参调用——`SessionConfig` 不再携带日志对象。写入仍只
发生在会话线程（worker 排空输出时、spawn 包装器收尾时），重连的前后
两次写由控制事件的接收顺序隔开，Mutex 只是把这个约定显式化；开关由
UI 线程经 `recorder::set_logging` 切同一个 Option，即刻生效。

## 后果

- 新增 `chrono` 依赖:本地时间戳格式化(`time` crate 的 local-offset
  在多线程下不可靠,不用)。
- worker 排空循环在日志开启时多做一次「新完成行」提取(从终端模型的历史
  网格取行文本,通常每轮 0~2 行)并按行追加;关闭时零成本(Option 早退)。
  性能验收需复跑确认。
- `SavedConnection`、`SshTarget`、`SessionConfig`、连接表单各加一个
  字段;`SessionConfig` 构造点(视图、e2e 与性能测试)同步补 `log` 参数。
- 日志文件无上限、无轮转:长时间刷屏会话会写出大文件,清理是用户的事
  (与 MobaXterm 口径一致);轮转作为后续独立决策。
- 需求规格 §3.2 与 README 同步更新。

### 转录拍频（2026-10-16 验收记）

落盘分两条路径，决定了「什么时候看到内容」：

- **每轮调** `transcript_lines`:只转录**已滚出屏幕进入历史**的完成行。
  短会话(登录 banner、几条命令,不到 30 行未触发滚动)期间日志看上去
  一直是空的——不是 bug,是设计上「已落盘即历史」。
- **退出时** `flush_screen_transcript` → `screen_transcript`:抓整屏,
  包括未滚出的行与跨轮次折行的挂起半行;尾部空行裁掉。

意图是「同一行只写一次」,避免短会话把同一段 banner 反复落盘。代价
是连接中的日志可能滞后于画面;长会话靠滚动把行送进历史,自动走
「每轮增量」路径。这条在用户复现「SSH 连上后日志只剩开始标记、推出后
正文全在」时定调为预期行为,不为短会话单独做实时刷写。
