# ADR-039：本地格重启恢复——工作目录与滚动回滚

状态：已接受（2026-10-21）。扩展 ADR-037（布局恢复）：在"新 shell"之上
补回**上次的工作目录**和**最近一段可见回滚**，接近 VS Code 的观感，但不做
进程常驻。§C.2 的「颜色/样式不保留」已被 ADR-040（全彩回滚）取代，其余
结论仍有效。

## 背景

ADR-037 恢复布局后每个本地格是空的新 shell，缺少上下文。用户要求"下次启动
能恢复此前状态"。对照 waku（egoist/waku）：它的内嵌终端由常驻 daemon 持有
PTY，客户端只渲染字节流，窗口重启后进程与回滚都还在——那是"进程连续"方案
（重连协议 + 跨平台宿主进程 + 升级兼容）。我们选择**视觉连续**：

- B：恢复上次的工作目录，新 shell 直接落在那里。
- C：恢复最近一段纯文本回滚，新旧内容之间插一条分界行。

SSH 格仍然完全不恢复（不落远端输出、不自动重连）。

## 决策

### B：工作目录采集

1. **宿主侧直接问操作系统**，不依赖 shell integration：zsh/bash 默认不发
   OSC 7，靠 shell 上报覆盖不了"用户什么都没配置"的场景。
   - Linux：`/proc/<pid>/cwd`（`read_link`）。
   - macOS：`lsof -a -p <pid> -d cwd -Fn`（libproc 结构体布局是运行期契约，
     ADR-028 已因此爆过一次雷，不复用手写结构体）。
   - Windows：读目标进程 PEB 参数块的 CurrentDirectory（`src/peb.rs`；
     2026-10-22 修订，取代最初"没有可靠的非侵入接口、返回 None"的边界
     判断）。跨进程 cwd 无文档化 API，`NtQueryInformationProcess` +
     `ReadProcessMemory` 是事实标准；CurrentDirectory 藏在参数块保留区，
     只能按固定偏移读，布局由对照 `GetCommandLineW`/当前目录的自身进程
     测试实证（ADR-028 的护栏模式）。
     **PowerShell 边界**（实机验证）：`Set-Location` 只改 runspace 的
     location，从不落进程 cwd（之后跑外部命令也不回写），PEB 采集对
     PowerShell 会话恒为启动目录——"cd 后退出"的目录在 PowerShell 下
     无法恢复，仍是平台能力边界；cmd 与 bash 类 shell（cd 落进程 cwd）
     完整恢复。
2. **采样时机**：只在有新输出后采样（命令执行完、提示符回来），且最多每
   2 秒一次；空闲的 shell 不反复起 `lsof`。目录变化经 `ControlEvent::CwdChanged`
   交给 UI，UI 随工作区立即落盘。
3. **恢复**：`workspace.json` 的本地叶记 `cwd`；新 shell 用它作为启动目录。
   目录已被删除时**不静默换目录**：PTY 启动失败在格中央显示原因，用户修好
   目录后重开即可。
   > 2026-10-22 拍板（曾试过「孤儿接管」后撤销）：「上次会话结束于」分界行
   > 与回滚恢复**只属于工作区恢复的格**。用户主动新开/重开的格是全新会话，
   > 不接管未被引用的孤儿回滚文件（曾实现"新开本地格改名接管最近孤儿"，
   > 实机使用后用户否决：新会话不该出现旧文案）。会话以 exit/关格收尾后，
   > 历史随下一次启动的孤儿清理删除，是预期行为。

### C：滚动回滚持久化

1. **文件按会话编号**：`<config>/scrollback/<number>.log`，与输出日志
   （`logs/`，用户显式开启的审计留档）分开。会话编号写入工作区（v2 叶字段）。
   > 2026-10-21 补充：显示编号与这里的 `<number>.log` 键已分离；关掉最后一个
   > 会话时显示编号归 1，持久化编号继续递增，避免复用回滚文件（ADR-042）。
2. **只记主屏、按逻辑行转录**：复用 ADR-017 的渲染后行文本（折行接续、
   `\r` 重绘只留最终态）；备用屏（vim/top/less）期间不写，避免用空屏幕覆盖
   上一份历史。颜色/样式不保留——恢复出来是黑白文本，这是"纯文本回滚"的
   明确取舍。（**已被 ADR-040 取代**：颜色与样式按 run 保留，恢复时按当前
   主题解析索引色。）
3. **上限**：每格最近 1,000 行且不超过 1 MB。空闲 2 秒（输出停下后）整写一次，
   会话结束（正常退出、关闭、连接失败、panic 之外的出口）再写一次；写失败
   保留上一份文件并退避重试，作为尽力而为的旁路（与 ADR-017 的日志失败语义
   一致，不打扰用户）。
4. **恢复**：新终端启动后、发出第一帧前，把文件内容灌进终端模型，并整体
   压入**滚动历史**——当前视口保持空屏，新会话的提示符从顶部开始，旧内容在
   它上方的历史里（对齐 Kaku 的 `prepend_primary_scrollback` 语义，ADR-037
   的布局恢复同理）。旧内容之后、视口之前插一条暗色分界行
   `—— 上次会话结束于 <时间> ——`，标记新旧边界。实现上是先按普通输出打印，
   再打「一屏减一行」个换行把内容顶进历史（正好全部滚出、不多留空行），
   最后只清视口（`CSI 2J`）回 home；`CSI 3J` 才会清历史，不能用。恢复的
   文本逐字符过滤控制符，手改过的文件也不会把转义序列注入终端；内容计入
   正常历史，搜索与回滚立即可用。
5. **清理**：工作区成功读取后，删除没有被任何格引用的 `scrollback/*.log`
   （关掉的格不再占磁盘）。工作区读失败时**不清理**——否则等于把用户历史
   删光。

### 明确不做

- 进程常驻（daemon 持有 PTY）与 SSH 会话恢复：见 ADR-037 的边界。
- 保留 ANSI 颜色/属性或序列化屏幕：体积与跨版本脆弱性不划算。
  （**已被 ADR-040 取代**：改为按样式 run 转录，不序列化整个屏幕。）
- 备用屏内容恢复：全屏程序的屏幕不是"历史"。

## 后果

- 重启后本地格的观感：上次的输出 → 分界行 → 新提示符（在原来的目录）。
  Windows 同口径（2026-10-22 修订；此前为"只能恢复布局与设置默认目录"）。
- 崩溃可能丢最后 2 秒的回滚；这是周期写的代价。正常退出/关格不丢。
- 回滚文件是明文：与输出日志同样的安全等级，但无需用户逐连接开启。
  之所以接受：它只含屏幕上已经可见的内容，且不超过 1 MB/格。

## 验证

- `cargo test cwd::`：读自身工作目录（Linux /proc、macOS lsof、Windows PEB）。
- `cargo test peb::`（Windows）：PEB 布局的实机实证——读自身 cwd 与当前目录
  一致、命令行与 `GetCommandLineW` 一致、不存在进程返回 None。
- `cargo test local_cwd`：cd → 采集 → 上报的会话级端到端（Windows 用 cmd
  验证 PEB 路径；PowerShell 的 Set-Location 不落进程 cwd，测不了目录变化）。
- `cargo test terminal::transcript_tests`：尾部回滚的行序与上限、恢复文本
  进历史（视口保持空屏）、分界行在旧内容之后、控制符过滤。
- `cargo test local_scrollback_is_restored_by_the_next_session`：真实会话输出 →
  关闭 → 文件落盘 → 新会话第一帧**不含**恢复内容（已进历史）→ 搜索命中旧输出
  并滚回历史，看到分界行。
- `cargo test local_cwd_changes_are_reported_for_workspace_persistence`：
  启动上报一次目录，`cd /tmp` 后上报新目录。
- 手工（2026-10-21 已验收）：开本地分屏 → `cd /tmp` → 退出应用 → 重启：本地格在 `/tmp`
  启动，旧输出带分界行回来；SSH 标签不出现。
