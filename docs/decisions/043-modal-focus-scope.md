# ADR-043：弹窗焦点作用域——输入框允许没有焦点

状态：已采纳（2026-10-21）

## 背景

打开 SSH 连接弹窗或设置弹窗时，焦点总是被塞给某个输入框（连接表单的主机框、
设置表单的终端字号框）。输入框一旦获得焦点就没有出口：点弹窗空白处不会取消
聚焦（点击被卡片截住），按键全部落进输入框，IME 也跟着弹。用户要的「看一眼
设置再关掉」被迫先经过一次输入。

根因不在输入框组件，而在弹窗打开路径：`open_*_form` 显式 `window.focus` 到
指定输入框，弹窗外壳没有自己的焦点归属，焦点只能落在输入框或穿透回终端。

## 决策

### 1. 弹窗外壳是焦点的归属层

`ui::panel::modal` 接受一个焦点作用域根（`FocusHandle`），卡片挂
`track_focus`：

- 打开弹窗：焦点落在作用域根，不落到任何输入框；
- 点卡片内输入框以外的区域：焦点回到作用域根（track_focus 的点击聚焦语义）；
- 作用域根上没有输入处理器：按键是 no-op，IME 不弹——「没有焦点」是真实状态。

### 2. 借用与归还

`open_modal` 记下打开前持有焦点的句柄并把焦点交给作用域根；`close_modal`
归还给原持有者（打开前没人持有就 `window.blur` 清空）。关闭路径（取消按钮、
点遮罩、Esc、提交成功）全部走 `close_modal`，归还逻辑单点。

确认浮层（关闭会话确认）同样处理：`open_confirm` 接管焦点（否则按键继续写进
前台程序），取消时归还；确认关闭时焦点交给关会话的路径（落到剩下的格）。

### 3. Tab 焦点环

模态内的 Tab / ⇧Tab 由应用根 `handle_key_down` 接住，沿「作用域根 → 各输入框
（视觉顺序）→ 作用域根」的环移动（`next_focus_index` 纯函数）。没有模态时不
拦，Tab 仍发给终端里的前台程序。各表单用 `focus_ring` 提供输入框序列，收起的
段落（跳板机、SOCKS 无目标行、未选自定义 Shell）不在环里。

### 4. 保留的既有焦点决策

- 载入已保存连接后聚焦主机框（ADR-026）：用户刚点了条目，是显式动作；
- 表单校验失败（转发表单）聚焦出错的框：用户接着改；
- SFTP 新建/重命名对话框聚焦名字输入框：单字段名称弹窗，输入就是目的。

### 5. 视图内弹层

SFTP 对话框/历史浮层与探针详情浮层同为 `panel::modal` 物种，各实体自持
`FocusHandle` 作用域；行为不变，只是补上作用域归属。

## 后果

- 弹窗打开时输入框一律无焦点，点哪个框哪个框才获得焦点；点空白回到无焦点态。
- 关弹窗焦点回到会话，终端立即恢复接收按键。
- 模态内 Tab 可走完一圈回到无焦点态；⇧Tab 反向。
- UI 编排不设单测（与仓库现状一致），环推进纯逻辑 `next_focus_index` 有单测。
  手工验收：开 SSH 弹窗 → 无输入框高亮、点空白不高亮、Tab 进出各输入框、
  Esc 关闭后终端立即可输入；设置弹窗同验；⌘W 弹确认 → Esc 取消 → 终端立即可输入。
