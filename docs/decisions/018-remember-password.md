# ADR-018:记住密码(OS 安全凭据存储)

状态:已接受(2026-10)

## 背景

P1 #7(`docs/context/mobaxterm-gap-and-priorities.md`):高频用户的每次连接
都要重输口令。需求规格 §5 早已给出契约:密码仅在用户显式选择「记住密码」
时写入操作系统安全凭据存储,默认不保存;应用配置只保存引用。

安全边界沿用 ADR-002:口令明文不进 `connections.json`、不进日志、不进
模型上下文;本 ADR 是「显式记住」这条既有许可的兑现,不是放松默认。

## 决策

### 存储:OS 安全凭据存储,条目键与保存的连接同构

`keyring` crate(3.x 线;4.x 已重构为核心+分体 store 的示例形态,不用)。
平台后端:macOS 钥匙串(`apple-native`)、Windows 凭据管理器
(`windows-native`)、Linux Secret Service(`sync-secret-service`)。

条目键:service 固定 `zhimaterm`,账号是 `用户@主机:端口`——与
`SavedConnection` 的唯一键同构,同名目标共用一条凭据(覆盖,不堆积)。

### 保存的连接只存引用标记

`connections.json` 的条目增加 `remember_password: bool`(serde 缺省
false,旧存档兼容)。它只说明「钥匙串里有一条对应凭据」,明文永不下盘
——既有的 no-secrets 测试(禁 `password:` 等字段名)继续盯住。

### 写入口唯一:保存连接时

- 表单「记住密码」勾选(默认关)+ 密码框非空 → 保存连接前先写钥匙串,
  成功才置 `remember_password` 并落盘;写失败(钥匙串锁定/不可用)以
  表单底部错误中止保存——用户意图是记住,静默降级成「没记住」会埋雷。
- 勾选但密码为空 → 表单报错「要记住密码,请先填写密码」,不保存。
- 取消勾选后保存 → 同步删除钥匙串条目(尽力而为,失败走保存错误通道
  提示),不让幽灵凭据留在钥匙串里。删除的判定基于编辑态里的旧条目;
  从新建表单覆盖同目标的边缘路径不追溯删除——那条凭据会在下次勾选保存
  时被覆盖,或随「忘掉连接」删除。

### 读:载入表单时回填

点开一条 `remember_password` 的连接:从钥匙串读出密码填进密码框,
「连接」即可直连。读不到(条目被用户在系统里删了、钥匙串不可用)就当
没记住:密码框留空、焦点落过去,回退为每次手输——不弹窗、不报错。
左栏列表行的「需输入」标记只给没记住的密码条目(ADR-002 的旧标记
在落地时漏了这条联动,记住密码的条目仍被标「需输入」,已修)。

### 删除:忘掉连接时联动

「✕ 忘掉这条连接」同时删除钥匙串条目;删除失败经既有的保存错误通道
提示(能存就得能删,删不掉要说)。

### 生命周期不变

钥匙串只在三个点被触碰:保存连接(写)、载入表单(读)、忘掉连接(删)。
密码进入表单后与手输完全同路:随连接交给会话、认证结束就地覆写,
不因「来源是钥匙串」多活一秒。

## 后果

- 新增 `keyring` 3.x 依赖;Linux 上需要 Secret Service(gnome-keyring 等)
  在跑,缺后端时保存即报错、读取回退手输(ADR-002 的「不可用即禁用」)。
- macOS 首次读写可能弹系统授权框(登录钥匙串),属预期交互。
- 单测不碰真实钥匙串(工作区规范:不动真实凭据存储):账号命名与表单
  接线走纯逻辑测试;真实钥匙串的读写删回路用环境变量门控的忽略测试,
  需要时手动跑。
- 表单基线(is_dirty)纳入勾选状态:勾选变化即视为改动,主按钮回到
  「保存并连接」;密码本身仍不参与比较。
- 需求规格 §5 与 README 同步;ADR-002 凭据节补修订记录。

## 修订（2026-10-28）：钥匙串只在「主动查看」与「连接确需密码」时读取

列表优先改版（ADR-048）落地后试用发现两个问题：点「编辑」载入表单时会把记住的
密码从钥匙串回填进密码框——每次开个表单就碰一次系统凭据存储，读得毫无必要；
「保存并连接」时表单里空密码会把钥匙串里已存的那份覆盖成空。修订：

- **读取时机只有两个**：密码框内右缘的「显示」（框内开关，`TextInput` 内置；
  再点「隐藏」换回掩码，内容留在框里），以及连接确实需要密码时（密码是唯一
  认证信息、框里是空的：列表「连接」对仅密码条目、「保存并连接」在建立连接前
  补填）。点「编辑」载入不回填、不碰钥匙串；已记住密码的条目，空框以一串星号
  示意「已存有密码」（`secret_stored` 标识态，独立字段维护，不掺进输入内容）；
  agent/私钥条目连接也不读——密码不是它们必需的素材。
- **空密码不覆盖**：已记住的条目保存时密码框为空 → 沿用钥匙串里已存的那份
  （身份没变就什么都不写）；表单校验随之放宽——「记住密码」勾着就算有认证信息，
  编辑已记住的条目不必重输密码。「新条目勾了记住却没填密码」的拦截移到外壳的
  保存路径（那里才知道钥匙串有没有旧的可沿用）。
- **身份迁移**：已记住的条目改了主机/端口/用户再保存，旧条目从旧身份名下搬到
  新身份名下（读取旧密码重写 + 删旧）；此前旧条目会永久孤儿，改主机后记住标记
  形同虚设。取消勾选的删除也改用旧身份（此前用新身份删，改过主机就删不中）。
- 读取时机与搬家用例按仓库惯例不设单测（会触碰真实钥匙串），单测覆盖表单侧
  的「记住即有认证信息」「载入不回填」「显示/隐藏只切掩码」，手工验收见
  `docs/context/manual-acceptance.md`。

## 修订（2026-10-29）：勾选框移除，输入即保存；连接期可问临时密码

- 动机：勾选框暗示「不勾就不存」是正确用法，实际反复造成「改了密码没生效」
  的误会（忘了勾）。需求 §5「仅在用户显式选择时写入」的口径废止，改为：
  **表单里输入了密码并保存，就写入钥匙串**；空框保存沿用已存的（不覆盖、
  不删除）；忘掉连接仍是删除凭据的唯一出口。
- `SavedConnection.remember_password` 字段保留（旧存档兼容读取），语义变为
  派生值「钥匙串里有这条的凭据」，保存时由「输入过密码或旧条目有凭据」折算；
  表单不再有开关，字段是条目带出的只读事实（供「显示」取回与空框沿用判定）。
- 保存侧校验移除（与 ADR-048 修订联动）：「没有认证信息」「要记住密码请先
  填密码」都不再拦——无静态素材的条目允许保存，连接时现场问密码。
- 连接期密码询问：认证逐层走到密码路（agent → 私钥 → 手头的密码都没成）
  且手头没有密码时，先自动试这条身份名下的**已存凭据**（此刻才读钥匙串，
  仍满足「确需才读」；自动应答占尝试额度之一、每次连接只自动一次防循环），
  没有或试错才经 `ControlEvent::PasswordRequired` 向 UI 要**临时密码**——
  只用于本次认证、**不落盘**（想下次免输去表单输一次）；答错重问，**三次**
  全错按普通认证失败收尾（防爆破不给无限重试），取消立即收尾。
  （时序勘误，2026-10-30 补：实现是 worker 无条件先发 `PasswordRequired`，
  钥匙串读取与自动应答发生在 UI 侧收到事件后、按身份比对进行——见下方
  第二批修订的 `credential_id` 口径；「先自动试、没人应才问人」的可观察
  行为不变。）
- 钥匙串读写失败从勾选行改贴表单底栏（动作级错误；勾选行已不存在）。
- 单测：保存计划矩阵改为输入即保存口径（输入 → 写、空框沿用、空框+迁移、
  无素材保存放行）；连接期询问走门控 e2e（询问连上、三次收尾）。

### 修订补记（2026-10-29）：询问门对齐键盘交互；询问携带身份

- **询问门 = 密码路**：临时密码的询问条件从「服务端声明 `password`」放宽为
  「`password` 或 `keyboard-interactive` 任一可用」——询问后实际走
  `try_password`（先键盘交互再 password），门必须与它的能力一致。此前只认
  字面 "password" 时，禁密码、只留键盘交互的服务器（堡垒机、2FA 常见形态）
  在 agent 失败后整段跳过询问、直接按认证失败收尾。服务器连键盘交互都不
  声明（纯 publickey）时仍不问（问了必然白问），失败报文补「服务器只接受
  {advertised}，没有密码可走的路」，不再让用户对着 agent 的报错猜。
- **询问携带身份**：`PasswordRequired` 带上此刻正在认证的身份
  （host/port/user），已存凭据的自动应答按这个身份读钥匙串。跳板认证走到
  密码路时带的是跳板身份——跳板口令不落钥匙串，取不到凭据就直接询问，
  目标的密码不会被自动应答发给跳板机的 sshd。
- e2e 新增 agent 回退用例（agent 有钥匙但服务器一把不认 → 仍询问 → 经
  键盘交互连上），另以禁 password 的容器形态先复现失败后验证修复；门判定
  矩阵走单测。
- **等答案不占连接预算**：密码询问等的是人，不是网络——拿到答复后认证
  预算重新起一段（OPEN_BUDGET），用户想密码想多久都不会让随后的认证带着
  过期预算必败；底栏同步显式「等待输入密码」态（秒表停走），不与
  「正在连接（Ns）」混用。

### 修订（2026-10-29，第二批）：凭据按条目 id 挂钥匙串；身份同构废止

- **条目键 = 连接的随机 id**（uuid v4）：钥匙串账号键从 `用户@主机:端口`
  改为保存条目的 id，一条连接一条凭据。同身份共用一条凭据（覆盖、不堆积）
  的口径废止——同身份的重复条目各有各的凭据；改主机/端口/用户不需要任何
  凭据迁移，「身份搬家读旧写新删旧」整段逻辑拆除。
- **读取时机不变**（仍是「显示」与「连接确需密码」两处），只是查找键换成
  id；连接期自动应答按 `SshTarget.credential_id`（记住了密码的保存条目才
  带）取凭据，配合 `PasswordRequired` 载荷里的身份比对，跳板询问不会误用
  目标凭据。
- **旧凭据不迁移**：旧存档条目载入时补发 id，`remember_password` 一并
  作废（当作都没存过）；按身份键写的旧钥匙串条目不再读取，成为孤儿——
  用户重输一次密码即落到新键。删除凭据的唯一出口仍是「忘掉连接」（按 id）。
- 表单：`has_stored_password` / 「显示」/「连接前补填」按编辑条目的 id
  读取；保存计划（ADR-048 修订）只剩「条目 + 手输密码」，空框沿用已存的
  那份（不写钥匙串）。
- 单测不碰真实钥匙串的口径不变：id 补发与标记作废走纯逻辑测试；真实
  读写删回路按 id 门控重写。
