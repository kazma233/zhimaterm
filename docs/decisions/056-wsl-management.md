# ADR-056：WSL 管理命令层与管理页（Windows）

状态：已接受（2026-11-16）。

## 背景

ADR-021 只解决了「开 WSL 会话」：入口弹选择模态、点发行版开会话。用户在
Windows 上的 WSL 日常工作流不止于此——装新发行版、删旧、设默认、终止、
全部关闭、更新 WSL、看磁盘占用与运行态、改 `/etc/wsl.conf`，此前都只能
进终端手敲 `wsl.exe`。这些操作全是对 `wsl.exe` 子命令的薄包装，与 021
的启动命令同源，不值得引入新的协议层；但命令面的域归属与 UI 组织需要
一次口径裁决。

## 决策

### 1. 命令层归 `local::wsl`，只做同步子进程包装

全部管理命令（安装、卸载、设默认、`--manage` 系列、终止、全部关闭、
更新、`--version`、`--list --online`、`/etc/wsl.conf` 读写与合并）住在
`local::wsl`，与 `launch_command` 同样钉死 System32 全路径（021 的防
PATH 劫持约束）；重定向下输出按 UTF-16LE 解码（021 已验证的事实约束）。
命令层只提供同步调用与纯解析（枚举过滤、conf 解析/合并、用户名白名单、
输出解码），不做线程调度——阻塞调用的编排（后台线程 + 回写实体）归页面。

### 2. 枚举沿用 021 口径，按列表需求扩展

注册表 Lxss 仍是主源（`Modern=1` 保留、docker-desktop/rancher-desktop
工具发行版过滤、默认置顶其余按名排）。扩展三项：运行态只认
`wsl --list --running`（注册表 `State` 停止后不回写，不可作运行态来源）；
磁盘占用 WSL2 取 `BasePath` 下 `ext4.vhdx` 文件大小、WSL1 递归求目录
大小，读不到省略；`BasePath` 规范化（`/` 转 `\`、去 `\\?\` 前缀）作为
安装路径展示。在线安装候选没有注册表来源，只能解析 `wsl --list --online`
（UTF-16LE）。

### 3. 页面形态：常显入口 + 管理模态，取代 021 的选择模态

底部 WSL 入口在 Windows 上常显（零发行版也可见——零发行版正是要呼出
在线安装），点击不再弹发行版选择模态，而是经浮层栈呼出**管理模态**
（ADR-044 的 ModalView）。页面实体（`WslManagerPage`）自持全部状态与
wsl.exe 编排，外壳只注入「开会话」回调；开会话走列表行主体点击并收掉
管理模态，终端标签留在原地不受影响。021「入口与交互」节的口径由本节
取代（见 021 修订段）。

### 4. 业务叠放链是 ADR-044 修订（纯栈叠放）的直接动因

管理模态 → 新增/分发版设置子模态 → 确认/提示对话框是真实的业务叠放：
「同物种互斥替换」会把底下的层悄悄丢掉，关掉栈顶表现为全部弹窗一起消失
（ADR-044 修订段的根因记录）。危险操作（`--unregister` 删除、
`--shutdown --force` 强制关闭）经全局 Dialog 叠确认，明示后果（删除 =
数据永久丢失）。

### 5. 安装：一步确认 + 用户名装后落地

「新增 WSL」模态同视图填写全部安装设置：镜像下拉（打开模态时才拉在线
候选，未就绪占位禁用、就绪后可点选或键盘 ↑↓/Enter）、安装位置
`--location`（原生目录对话框 rfd 选取，回填后仍可手改）、自定义名称
`--name`、自定义用户名、磁盘大小 `--vhd-size`（留空用默认），档位
`--no-launch` / `--web-download` / `--fixed-vhd` 勾选。「安装」固定在
模态动作区，未选发行版不执行，确认后才执行并关模态。自定义用户名在装
完后以 root 创建（`useradd`，busybox 系退 `adduser -D`，sudo/wheel 组
尽力而为），名字过白名单校验（字母或 `_` 开头、仅字母/数字/`_.-`）防
shell 注入，再经官方 `--manage --set-default-user` 落地；创建会短暂
启动一次发行版，「装完不自动启动」时随后终止。

### 6. wsl.conf GUI：原文基底合并，stdin 整文件写回

分发版设置模态呈现 `/etc/wsl.conf` 的分组控件（启动/网络/互操作/自动
挂载/GPU/时间/用户），每项下挂官网（wsl-config）解释与设置状态行；未
显式设置的键按官方默认值展示并带「默认」徽标，首次操作即写入显式值，
徽标消失。读取**不自动启动**停着的发行版——先显示「未运行」态，用户点
「启动并读取」确认后才启动并后台读取（运行中的直接读取）。保存以读到
的原文为基底合并（只改管理的键、保留用户自定义段与未知键；文本留空 =
删键恢复默认），内容经 stdin 整文件写回，不进命令行参数；提示终止并
重新打开后生效。同模态「管理操作」组承载 `wsl --manage`：稀疏 VHD
开关（`--set-sparse`）、调整磁盘大小（`--resize`）、移动到新位置
（`--move`，确认对话框、要求停止）。

### 7. 反馈口径：UI 可见的成功不弹窗

命令结果以提示弹窗（单按钮「知道了」，失败红字）反馈，但 UI 上已能体现
的成功（装完出列表、设默认标记移动、终止/删除/全部关闭的运行态变化）不
弹；无可见变化的操作（稀疏/移动/调整大小/更新）与保存设置提示保留。
完成即重查注册表刷新列表；有命令运行中时禁用全部操作入口。模态顶部
只读展示 `wsl --version` 的版本信息与进行中的命令名。

### 8. 版本只展示不操作

WSL 大版本、发行版 WSL1/2 只作展示；不提供导入与 WSL1↔2 转换（延续
021 的需求口径）。

## 后果

- `rfd 0.15` 成为 app crate 的 Windows 依赖（目录选择对话框，仅
  `#[cfg(windows)]` 接入）。
- 测试 seam：`local::wsl` 纯解析层（`select_distros` fixture、
  `parse_wsl_conf`/`merge_wsl_conf`、`is_valid_user_name`、UTF-16LE
  解码）单元测试覆盖；wsl.exe 子进程调用与页面交互不设单测（与仓库
  现状一致），行为口径以需求规格 §3.2 为准，首次落地走人工验收清单。
- 需求规格 §3.2（WSL 管理条目）与界面骨架（入口常显）同步更新；
  ADR-021 的入口交互口径由本 ADR 取代。
- 管理链的叠放语义与滚动状态槽冲突的取证见 ADR-044 修订段与
  [叠放模态滚动失效排障](../context/overlay-stack-scroll-troubleshooting.md)。
