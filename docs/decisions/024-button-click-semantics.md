# ADR-024:按钮基础组件与点击语义

状态:已接受(2026-10)

## 背景

按钮此前在按下(MouseDown)瞬间触发:按住拖出按钮松开、按错了想反悔,动作
照样发生。触发判定散落在各调用点的 `on_mouse_down` 里,个别按钮还要额外
`stop_propagation` 防止惊动父级,写法不一、业务各自为政。

## 决策

- `ui::panel::clickable` 是按钮的唯一基座:gpui `on_click` 语义——按下与
  松开都落在按钮自身盒子内才触发。按住拖出去松开不触发;按在别处拖进来
  松开也不触发。命中区域就是元素盒子,与可见边界一致,没有看不见的扩展热区。
- `primary_button`/`secondary_button`/`chip`、字体下拉的选择框与选项行、
  右键菜单条目、WSL 选择行、SFTP 面板的全部按钮、连接/设置模态的按钮,
  一律经由基座或同语义的 `on_click`;业务只给 id 与回调,不写按下/松开的
  判定,也感知不到判定细节。
- 嵌套在可点行里的 ✕(关闭会话、忘掉连接)用 `occlude` 挡住按下——所在行
  不因这次按下而激活;删除动作仍走自己的点击。
- 保持按下语义的例外(不是按钮,不改):模态/下拉/右键菜单的遮罩(点空白即
  收起)、终端网格的鼠标输入(选区与上报)、SFTP 条目的左键选中与右键菜单、
  拖拽手柄(侧栏调宽、面板调宽、分割条)。

## 后果

- 误触面变小:拖出按钮松开不再误发动作;连接、递归删除确认这类重动作多了
  「松开才算」的一层保险。
- 新增按钮一律走基座,不再手写 `on_mouse_down`;元素 id 由调用方给(gpui
  的点击状态按元素 id 记账)。
